## 4. 本课新增实测事实（cjc 1.0.5 实测）

> ⚠️ 同上：这些都是**版本相关**的事实，换机器先用 `cjc -v` 自查。

| 事实 | 说明 |
|---|---|
| 未使用的变量会**报警告**（不是错误） | `warning: unused variable: 'n'` —— `L3-C` 你会撞上 |
| 判题 harness 现在**容忍编译警告** | 警告会显示为 `(编译警告)` 并继续判分 |
| 修复前的行为 | 只要 cjc 往 stderr 写一个字，判题脚本就会**整个崩掉**（`$ErrorActionPreference='Stop'` 把原生 stderr 当成终止错误）。已改用独立进程捕获 |
| `split(" ")` 不合并空格 | `"  1   2  ".split(" ")` → 8 个元素，6 个是空串 |
| 空串喂给 `Int64.parse` | 抛异常 `The string is empty.` |

### 关于 `L3-C` 那个警告

你会读到 `n` 但**用不上**（直接切分第二行就行），于是 cjc 警告 `unused variable:'n'`。

这**不是错误，也不扣分**——真实考试里无所谓。但记住：
> **仓颉的警告是免费的体检。** 它在告诉你"你读了这个值却没用它"，
> 而这类地方往往就是"我漏处理了某种情况"的信号。考试时无视它，练习时值得看一眼。
