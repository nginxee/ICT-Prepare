```
   │  └─ ...
   └─ answers\

      └─ L*.cj                 ← 判题前自动从 default\src 同步过来
```

**怎么跑：** 在 `drills\DSA_Advanced_topic` 目录下


## 4. 实测陷阱速查卡（cjc 1.0.5 实测）

> ⚠️ 下表是在一台 **cjc 1.0.5** 的机器上实测的。换机器请先用 `cjc -v` 自查版本，尤其是 ormat 那几条。

> 这些是**语义事实**，不是解法。用不用得上、怎么用，你自己想。

| 事实 | 数值 |
|---|---|
| `getStdIn(): ConsoleReader`、`ConsoleReader.readln(): ?String` | 在 `std.env` |
| **读到输入结束** | `readln()` 返回 `None` |
| **读到空行** | `readln()` 返回 `Some("")`，**和 `None` 是两回事** |
| 0 字节空输入 | 第一次调用就返回 `None` |
| 末尾换行 | **不会**多出一个空行 |
| 输入是 CRLF | 换行符被剥掉，`"42\r\n"` 读出来 size=2 → **安全** |
| `Int64.parse(" 5")` / `("5 ")` / `("+5")` / `("")` | **全部抛异常**（不宽容空白，不接受 `+`） |
| `Int64.parse("05")` | `5`（前导零可以） |
| `"  1   2  ".split(" ")` | **8 个元素**，6 个是空串 → 配合 parse 会崩 |
| `split(str, removeEmpty!: Bool = false)` | 标准库自带去空串开关 |
| `String.size` | **UTF-8 字节长度**，`"汉字".size == 6` |
| `Float64.format` 语法 | `[flags][width][.precision][specifier]`，**四段全部可选** |
| `Float64.format(".3")` / `("1.3")` | `3.142` —— **宽度可以省略**，两者等价 |
| `Float64.format("")` | `3.141590` —— **空格式串合法**，默认 6 位小数 |
| `Float64.format(".3e")` / `(".3g")` | `3.142e+00` / `3.14` —— **可用** |
| `Float64.format(".3f")` / `("f")` / `("1.2f")` | **抛异常** —— 只有 `f`/`F` 是坏的，`e`/`g` 是好的 |
| `Int64.format("08x")` | `000000ff`；`x`→`ff`、`X`→`FF`、`o`→`377`、`b`→`11111111`、`#x`→`0xff` |
| `Int64.format("5.3")` | `"  007"` —— 整数 precision = **最少位数**（补零），不是小数位 |
| `format` 在哪 | `std.convert` 的 `Formattable`，**必须先 `import std.convert.*`** |
| 缺 import 的报错长相 | `error: undeclared identifier 'format'`（**只字不提 import**） |

### 4.1 格式串完整实测表（2026-09-29 修订）

KB 原文（`std.convert.interface.formattable`）：格式串结构为
**`[flags][width][.precision][specifier]`** —— 四段全在方括号里，**全部可选**。

**Float64（以 `-3.14159` 为例）**

| fmt | 输出 | 说明 |
|---|---|---|
| `10.3` | `    -3.142` | 宽度 10，默认右对齐 |
| `-10.3` | `-3.142    ` | `-` = 左对齐 |
| `010.3` | `-00003.142` | `0` = 零补齐 |
| `.3` | `-3.142` | **精度可单独使用** |
| `""` | `-3.141590` | 空串合法 → 默认 6 位小数 |
| `.3e` | `-3.142e+00` | ✅ 可用 |
| `.3E` | `-3.142E+00` | ✅ 可用 |
| `.3g` / `.3G` | `-3.14` | ✅ 可用 |
| `.3f` / `.3F` | **抛 IllegalArgumentException** | ❌ **只有 f/F 坏** |

**Int64**

| fmt | 输出 | 说明 |
|---|---|---|
| `8` | `     255` | 宽度 8 |
| `08` | `00000255` | 零补齐 |
| `x` / `X` | `ff` / `FF` | 十六进制 |
| `08x` | `000000ff` | 宽度 + 进制 |
| `#x` | `0xff` | 加前缀 |
| `o` / `b` | `377` / `11111111` | 八进制 / 二进制 |
| `5.3` | `  007` | precision = **最少位数** |
| `-8` | `-255    ` | 左对齐 |

> ⚠️ 未验证：`+` 标志（我只用负数测过，看不出效果）。KB 说"`+` 总是显示符号"。
>
> 📌 相关场景示例：`examples.text.numeric-format-table`（组合 width/precision/对齐做稳定列宽）。

### 4.2 勘误：第一版里我写错的地方

| 我原来写的 | 实际 | 怎么发现的 |
|---|---|---|
| "宽度必须写" | **错**。`[width]` 可选，`.3` 完全合法 | 学员 L1-C 用了 `format(".3")` 且 5/5 通过 |
| "浮点上任何带 `f/F` 的格式串都不可用" → 暗示浮点不能用说明符 | **错**。只有 `f`/`F` 坏，`e`/`E`/`g`/`G` 都正常 | 本次全量实测 |
| （一度认为）KB 没有格式串语法文档 | **错**。KB 写得很清楚，是我检索词不对 | 我用「格式化格式串／说明符」，KB 用的是「**格式串**」 |

> **教训（这一条对你比上面三条更重要）**：
> ① 教练的断言也要过编译器 —— 我"宽度必须写"是从一次实验**外推**的，没做对照实验；
> ② 检索不到不等于库/文档没有 —— **换词再搜一次**，别急着宣布"知识缺口"。
>
> 顺带：你写的 `.3` 比我给的 `1.3` **更简洁**，这是你赢了。

## 6. 环境相关（会咬你，先记下）

> 这一节是在 **Windows + 中文系统（ANSI 代码页 936）** 上踩出来的。
> 换机器不一定完全相同，但值得先看一眼——三条都是"静默失效"型故障。

1. **判题入口用 `.cmd` 启动器，不要用 `pwsh -File judge.ps1`。**
   启动器额外做了三件事：切到它自己的工作目录、双击时暂停等你看结果、把参数原样透传给脚本。

2. **Windows PowerShell 5.1 按系统 ANSI 代码页解码无 BOM 的 UTF-8 文件。**
   - 这就是为什么 `judge.ps1` / 启动器都保持**纯 ASCII** —— 中文全在 `messages.json`，
     由脚本**显式按 UTF-8 解码**，不受代码页影响。
   - **你自己造测试输入时别用会写 BOM 的保存方式**（如 `Set-Content -Encoding UTF8`）。
     带 BOM 的输入文件会让第一行前面多一个 `﻿`，`Int64.parse` 当场抛异常——
     而你会以为是自己代码错了。题库自带的 `in\*.txt` 已经是无 BOM 的，放心用。
   - `.cj` 源码带不带 BOM 都能编译（已实测），不用管。

3. **`chcp 65001` 会让 `[Console]::ReadLine()` 立即返回 EOF**，
   所以启动器里**故意不写 `chcp`**。谁要是"顺手修好编码"加上它，交互提示会**静默失效**。
