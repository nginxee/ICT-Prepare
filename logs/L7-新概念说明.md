# L7 · 新概念：从「编排」到「算法」

> 前六关你练的是**编排**（读进来 → 用库整理 → 按格式输出）。
> 从这一关开始，题目要求你**想出一个做法**，而不是"查一下有没有现成的库"。

---

## 0. 这一关的性质变了

| | L1–L5 | **L7** |
|---|---|---|
| 难点 | 输入读对、格式写对、库用对 | **想到一个足够快的做法** |
| 知识来源 | 本机知识库（语言/库/工具链） | ⚠️ **知识库不含算法专题**（计划 §0-B） |
| 通过方式 | 查文档 → 写 | **推理 → 试 → 改** |
| 判题反馈 | 对 / 错 | 对 / 错 / **超时** |

### 关键设计：每道题的朴素做法**必然超时**

大用例的规模被我调成"朴素做法 ≈ 4×10¹⁰ 次运算"，而判题**单用例上限 5 秒**。
**这不是刁难——是让你无法靠蛮力过关，必须真的想到那个概念。**

> ✅ 已实测确认：`L7-A` 的朴素 O(n·m) 写法在用例 03 上被判**超时**；
> 正确的前缀和写法同一用例 **261 ms**。

### 题面里有「思考方向」，没有解法

每题都标了**考察概念**，并给一段**引导性提问**。那是思路，不是答案。
你要做的是把那个提问回答出来，然后写出代码。

---

## 2. `L7-D` 是最容易错的一题

二分查找的**边界**是经典陷阱。自测这几个（我判题里都放了）：

- 目标比所有元素都**小** → 应该是 `1` 或 `-1`
- 目标比所有元素都**大** → `-1`
- 目标正好是**第一个元素** → `1`
- 目标有**重复**，要找**第一次**出现 → 不能找到就返回
- `n = 1`

## 3. `L7-E`：专门给你补那道墙

你在 `L5-D` 和 `L6-B` 里**两次**撞在同一处：

```cangjie
sort(map, lessThan: ...)      // ❌ sort 没有 HashMap 重载
```

`L7-E` 把这件事**单独拎出来考**，没有 Top-K 的干扰。核心两句话：

1. **`sort` 的 12 个重载只收 `Array` / `ArrayList` / `List`** —— 没有 `HashMap`
2. **「排序一个 map」本身没有意义** —— map 是**查找结构**（键→值），不是序列

> **排对象，不排容器。** 你要排的是 map 里的**条目**（每个条目同时带"单词"和"次数"）。

排序规则你**已经在 L5-C 写对过**（两个键、方向相反）—— 把「分数/姓名」换成「次数/单词」而已。

## 5. 我修了一个判题脚本的 bug（会咬到你）

验证 L7-A 时判题**整个挂死**（10 分钟没动）。查出来是**我的 harness 有 bug**：

| | |
|---|---|
| 触发条件 | 用例的输入 ~2MB **且** 输出 ~1MB |
| 原因 | 我先把整个 stdin 同步写进管道，但程序边读边往 stdout 写。stdout 管道缓冲填满 → 程序阻塞 → 不再读 stdin → 我这边永远写不完 |
| 后果 | **死锁**。而且连超时都触发不了，因为代码卡在 `WaitForExit` 之前 |
| 修复 | 改成**文件重定向**，完全不碰管道 |

> ⚠️ **这条对你很重要**：如果你在这次修复之前写出了 L7-A 的正确解，
> 判题会**挂死**，而你会以为是自己的代码有问题。
> **不是你的问题，是我的工具。**

顺带：这次验证又抓到我**两个期望值写错**（`L6-B` 用例 11、`L7-E` 用例 01）。
所以判题数据本身也是被验证过的 —— 但如果你怀疑某个期望值是错的，**直接问我**，别默认"一定是我错了"。
