## 0. 上一课的两件事

### 0.1 你做对了：`L4-C`

```cangjie
match (input_stream.readln()) {
    case Some(value) => tmp = value
    case None => break          // EOF

```

**这是标准答案的写法** —— `None` 判结束、`Some("")` 判空行，两者分得干干净净。说明你完全会。

### 0.2 但其余 5 个文件没改

`L2-A/B/C`、`L3-D`、`L4-A`、`L4-B` 仍然是全局 `readln()` + `isEmpty()` 判结束。
交叉测试结果：`L2-A` 失败 3 个用例、`L2-B` 5 个、`L2-C` 5 个。

**我重新理解了一下你的策略**：你不是不会，你是**按规格选工具**——题面保证没有空行，就用最省事的写法；`L4-C` 明说有空行，就换 `?String`。这个策略是自洽的。

### 0.3 所以我把要求收窄成一条

**不再要求你返工那 5 个练习文件。** 只要求一件事：

> ### `oj_tpl` v3 的读循环必须是**无损**的。

理由不是「更鲁棒」，而是：

**模板的职责是"不丢信息"，不是"替你决定策略"。**

- 写模板的时候，你**还不知道题目规格**。
- 如果模板用 `isEmpty()`，它就把「空行」和「结束」永久合并了 —— 此后**每个问题**都得回头想"这题要不要换"。
- 如果模板用 `?String` + `match`，它把 `Some("")` 和 `None` **原样交出来** —— 每道题自己决定：
  - 空行要**忽略** → `if (line.size == 0) { continue }`
  - 空行是**组分隔符** → `case Some("") => 开新组`
  - 空行**不该出现** → 什么都不写，等于没这回事

**三种策略都写得出来，因为信息没丢。** 而用 `isEmpty()`，第二种（空行当分隔符）**永远写不出来** —— 那类题在综合应用题里是存在的。

代价：零。收益：模板从"需要看规格才能用"变成"拿来就能用"。

## 3. 关键契约（KB 原文 + 本机实测）

### 3.1 `std.sort` 有 12 个重载 = 3 容器 × 4 比较器风格

| 比较器风格 | 声明形态 | 什么时候用 |
|---|---|---|
| 默认 | `sort(data)` | 元素实现 `Comparable<T>` |
| `key` | `sort(data, key!: (T) -> K)` | **单个**派生键 |
| `lessThan` | `sort(data, lessThan!: (T, T) -> Bool)` | 自定义 / **多字段**比较 |
| `by` | `sort(data, by!: (T, T) -> Ordering)` | 已经有现成的 `Ordering` 比较器 |

公共命名参数：`stable!`（稳定排序）、`descending!`（降序）。

⚠️ **最容易踩的一条**（KB 原文）：

> 调用命名参数时写 `lessThan: {left, right => ...}`，**不写声明中的感叹号**。

即：**声明**里是 `lessThan!: (T,T) -> Bool`，**调用**里写 `lessThan: {...}`。

`Ordering` 在 `std.core`，三个值：`LT` / `EQ` / `GT`。

### 3.2 `HashMap`

| 成员 | 签名 | 说明 |
|---|---|---|
| `get` | `get(key: K): ?V` | **返回 `Option`** —— 键不存在时是 `None` |
| 索引器读 | `operator [](key: K): V` | 直接取值 |
| 索引器写 | `operator [](key: K, value!: V): Unit` | 赋值/更新 |
| 迭代 | `for ((k, v) in map)` | 双变量解构遍历 |

> 「计数」的惯用形状：`map[k] = (map.get(k) ?? 0) + 1`
> —— 这里又见到第一课那个 `??`：**把「缺失」当成 0**，这一次是对的用法。

### 3.3 `HashSet`

`add` / `contains`；迭代顺序**不保证** —— 要按顺序输出就**必须再排序**。

## 4. 顺带一个「省时间」的观察（与你「同分按用时」有关）

你 `L3-D`、`L4-A`、`L4-B` 都是这个形状：

```
把所有结果先存进 ArrayList  →  循环结束后再统一 println
```

**只有「输出顺序 ≠ 输入顺序」时才需要缓存。**

| 什么时候真的需要缓存 | 例子 |
|---|---|
| 要排序 | `L5-C`（要按分数排） |
| 要算全局量再输出 | `L4-C`（先读完才知道总和） |
| 要分组 | 组内数据凑齐才能算 |
| **输出顺序 = 输入顺序** | **`L3-D` / `L4-A` / `L4-B` → 边读边打印，不用缓存** |

你的 `L4-B` 是 46 行（struct + ArrayList + 两段循环），边读边打印大约 **18 行**。

**考试 120 分钟 3 题，同分按用时排名。** 少写 28 行 = 少 28 行可能出错的地方 = 更快交卷。
这不是"代码优雅"，这是**用时**。
