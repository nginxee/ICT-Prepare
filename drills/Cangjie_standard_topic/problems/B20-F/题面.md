# B20-F · ★ 读写锁：多读单写

**关卡**：B20 · 并发  ★挑战
**对应博客**：《跟我一起学“仓颉”编程语言》第 60·61·62·63·64·65·66·67·68·69·70 篇
**提交文件**：`answers/B20-F.cj`

> n 个写者各往余额里加 a，m 个读者各读一次余额；写用写锁、读用读锁，最后输出读者总次数与最终余额。

## 知识点

- ReadWriteLock 构造
- readLock 读锁共享
- writeLock 写锁独占
- AtomicInt64 计数
- Future.get 收齐后再输出

## 输入

一行，三个整数 n m a（单个空格分隔）：n 个写者、m 个读者、每次加 a。

**数据范围**：1 ≤ n ≤ 8；1 ≤ m ≤ 8；1 ≤ a ≤ 100

## 输出

两行：`reads=<读者读到的总次数>`、`balance=<n * a>`。

## 样例

**样例 1**

```
输入：
3 2 10
输出：
reads=2
balance=30
```

**样例 2**

```
输入：
1 1 7
输出：
reads=1
balance=7
```

## 提示

`ReadWriteLock()` 的 `readLock` 可以多个读者同时持有，`writeLock` 是独占的；**共享的可变状态必须放进类字段** —— `spawn { 余额 += a }` 直接捕获可变局部变量会编译不过（报 lambda capturing mutable variables）；读者计数用 `AtomicInt64` 的 `fetchAdd`。所有 `Future` 都 `get()` 收齐之后再打印，输出才稳定。
