## 2. 机械校验（全部通过）

```
D:\python\python.exe _build\check.py         → 72 problem(s) checked, 0 FAIL
D:\python\python.exe _build\check_doc.py     → 72 problems, 0 mismatch(es)
```

`check.py` 逐题检查：

- 题面必备小节齐全，且**不含** `## 知识点` / `## 提示`（v2 起搬进 notes）
- 题面含 `answers/<ID>.cj` 提交路径与 `notes` 链接
- **该关的 `notes\D<nn>.md` 存在**，且 `### 学术` / `### 实操` / `### 建议` 各 4 次、`建议` 出现在 `学术` 之后
- in/out 文件名一一对应且为 `01..05`；所有 `.txt` 为 UTF-8 无 BOM + LF + 末尾恰好一个换行 + 非空 + ≤8 MB；out 无行尾空格
- **题面里的「样例 k」与 `in/0k.txt`、`out/0k.txt` 逐字符一致**

`check_doc.py` 逐题检查：题面的关卡名与标题和 `大纲.md` 第 2 节长表一致（防止文档与题库漂移）。

## 4. 数据的可信度来自三层独立核对

1. **期望输出由参考实现产出**，不是手写：`_build\gen\<ID>.py` 造输入 → `_build\ref\<ID>.cj` 跑出输出。
2. **题面样例反向对照文件**：`check.py` 强制样例与 `in/0k.txt`/`out/0k.txt` 逐字符相等。
3. **第二算法交叉验证**（出题时逐题做过，不随代码入库）：每题用 Python 以**不同于参考实现的算法**
   重算 5 个用例（小用例暴力枚举/逐格累加，大用例独立实现 + 随机抽样暴力），与 `out\` 逐字节比对。
   例：D8-C 用逐格累加验容斥、D9-D 枚举全部 C(n,3) 三元组、D17-D 全排列、D18-D 迭代加深求编辑距离。

## 6. 两个环境事实（写下来免得下次重新踩）

- **`gen_out.ps1` 打印的耗时虚高约 1.0 s**：PowerShell 5.1 的 `Start-Process -Wait` 在本机有固定开销
  （空程序也要 1.03 s）。真实耗时看 `judge.ps1` 的每用例 ms。
- **`cjc` 的栈是可增长的**：实测非尾递归 10⁶ 层正常返回，不要写"递归 1e5 会爆栈"这类断言。
  详见 `..\大纲.md` 第 4 节「与实测对齐的口径」。
