# D18 · 动态规划

> 4 个单元，每个单元三段：**学术**（定义/不变量/为什么对）→ **实操**（仓颉写法/边界/实测）→ **建议**（做完对应题目再看）。
> 写 DP 只需要回答三个问题：**状态是什么**（含哪个元素、是否恰好）、**转移怎么来**（末位相等就用前一位，否则枚举最后一个操作）、**滚动方向朝哪**（0/1 背包必须倒序）。本关四道题正好各示范一次。

## 18.1 最大子段和（D18-A）

### 学术

- 状态：`dp[i]` = **必含 `a[i]`** 的最大子段和（"必含"就是"非空"的保证）
- 转移：`dp[i] = a[i] + max(0, dp[i-1])`——前面那段为负就丢掉，从 `a[i]` 重新开始。答案取 `max dp[i]`（不是 `dp[n-1]`，最大子段可以在任何位置结束）
- 非空边界：全是负数时答案是**最大的那个负数**；`dp` 初值必须取 `a[0]`，不能取 0
- 滚动方向：只用 `dp[i-1]`，所以一个变量就够（O(1) 空间）；"重新开始"的位置就是候选左端点
- 量级：n × 10⁹ = 2×10¹⁴ ≤ 9.2×10¹⁸，`Int64` 安全

### 实操（仓颉）

- 主循环：`if (cur < 0) { cur = a[i] } else { cur = cur + a[i] }`，同时用严格 `>` 更新 `best`
- 要输出左端点就别在滚动里硬猜：算完 `best` 后开前缀和 `pre[0..n]` + 后缀最大值，第二趟找"最小的 l 使 `存在 r ≥ l` 满足 `pre[r] = pre[l-1] + best`"，再找最小的 r——两步都是 O(n)
- 说明里要求"左端点最小、再右端点最小"，用严格 `>` 更新 `best` 才不会把更靠后的窗口记进来
- 实测：D18-A 的 05 用例（n = 2×10⁵、±10⁹）在 judge 里约 181 ms，答案 `max=343982387428`（3.4×10¹¹，超过 32 位）

### 建议（做完 D18-A 之后看）

- 自检：单元素负数（`[-5] → max=-5`）、全负数且最大值出现多次（取最靠前）、全 0（`l=r=1`）
- 高频错法：把答案写成 `max(0, dp[n-1])`（空子段）、或者把初值写 0 导致全负时输出 0
- 若题目加"子段长度至少 k"，就不能只留一个变量了，要在 `dp` 维上再挂一维

## 18.2 0/1 背包（D18-B）

### 学术

- 状态：`dp[j]` = 容量**恰好**为 j 的最大总价值（"恰好"是这题与"不超过"的分水岭）
- 转移：`dp[j] = max(dp[j], dp[j-w] + v)`，每件物品最多用一次
- **滚动方向：一维数组必须 `j` 从 V 递减到 w（倒序）**。正序会让 `dp[j-w]` 在本轮已经被 `+v` 更新过，同一件物品被重复使用，那就变成完全背包了
- "装不满"用哨兵表示：`dp[0] = 0`、其余 `-INF`；`dp[j-w] == -INF` 的转移必须跳过，否则哨兵会把假可行状态染进来
- 复杂度 O(n·V) = 10⁶ 次转移；总价值最大 n × 10⁹ = 10¹²，`Int64`

### 实操（仓颉）

- 哨兵取 `-4611686018427387904`（约 `-1 << 62`）：既远小于任何合法价值，`+ v`（≤ 10⁹）也不会下溢
- 内层写 `var j = cap; while (j >= w) { ...; j = j - 1 }`；`w > cap` 的物品整个跳过
- 最后 `if (dp[cap] == NEG) { println("-1") } else { println("best=${dp[cap]}") }`
- 实测：D18-B 的 05 用例（n = V = 1000）在 judge 里约 75 ms

### 建议（做完 D18-B 之后看）

- 自检：唯一物品重 2、容量 3（必须 `-1`，不是 100）、恰好装满与"不超过"的差别用一个 w = V 的单件验证
- 高频错法：正向枚举 j（重复使用）、用 0 当不可行标记（0 是合法价值）、用 `Int64` 最小值当哨兵（加 v 会溢出）
- 需要输出选了哪些物品时，倒序的一维数组不再够用，要么留二维表，要么额外存"每件物品的决策"

## 18.3 LIS（D18-C）

### 学术

- O(n²) 状态：`dp[i]` = 以 `a[i]` **结尾**的最长严格上升子序列长度；转移 `dp[i] = 1 + max{ dp[j] : j < i, a[j] < a[i] }`，答案取 `max dp[i]`
- O(n log n) 状态：`tails[k]` = "长度为 k+1 的上升子序列的**最小可能结尾**"。对每个 `a[i]` 二分找到第一个 `tails[mid] ≥ a[i]` 的位置覆盖它（找不到就追加）
- 为什么 `tails` 的长度就是答案：`tails` 关于 k 严格递增（长度更长的子序列结尾必然更大），替换只让结尾变小、不破坏这条不变量，因此每个位置都对应一个真实存在的子序列
- 严格上升用 `tails[mid] >= x`；若写成 `>` 就变成"最长不下降"了
- 更新方向：`tails` 从左到右一遍扫、**原地覆盖**（它的长度只增不减，不需要保存历史）；O(n²) 版本则要保留整个 `dp` 数组
- 方案重建：先算 `suf[i]` = 以 i **开头**的 LIS 长度，再从前往后贪心取"`a[i]` 比上一个选中值大且 `suf[i]` 够长"的第一个 i

### 实操（仓颉）

- 二分自己写：`while (lo < hi) { let mid = (lo + hi) / 2; if (tails[mid] >= x) { hi = mid } else { lo = mid + 1 } }`，`lo` 就是要覆盖的位置
- `suf[i]` 不需要另写一套算法：把数组反转并取负后跑同一个 `tails` 过程，"以 p 结尾"的长度正好等于原数组"以 n-1-p 开头"的长度
- 重建时维护 `remain`（还差几个），条件 `a[i] > lastVal && suf[i] >= remain` 就选它
- 实测：D18-C 的 05 用例（n = 10⁴）在 judge 里约 86 ms；O(n²) = 10⁸ 次比较也能勉强通过，但 n 再大就只能用二分版

### 建议（做完 D18-C 之后看）

- 自检：全相同（`5 5 5 5` 长度 1，方案取第一个 5）、严格递减（长度 1）、以及 `3 4 5 1 2 3 6`（长度 4，方案是 `3 4 5 6` 而不是 `1 2 3 6`）
- 高频错法：`>=` 与 `>` 写反（严格/不严格混掉）、方案"从 dp 最大值往回跳"（并列时给不出字典序最小）
- 求"下降子序列/不上升子序列"只需把元素取负或反转后套同一份代码

## 18.4 编辑距离 / LCS（D18-D）

### 学术

- 状态：`dp[i][j]` = 把 `s1` 前 i 个字符变成 `s2` 前 j 个字符的最少操作数
- 转移：`s1[i-1] == s2[j-1]` 时 `dp[i][j] = dp[i-1][j-1]`；否则 `dp[i][j] = 1 + min(dp[i-1][j-1], dp[i-1][j], dp[i][j-1])`（分别对应替换、删除、插入）
- 边界：`dp[i][0] = i`（删空）、`dp[0][j] = j`（插入）；表大小是 `(n+1) × (m+1)`，少一行一列就会越界
- 滚动方向：只依赖上一行与左边一列，所以两行滚动可做 O(m) 空间；但**重建方案需要完整表**，本题要输出 `script`，就老老实实留二维表
- 与 LCS 的关系：只允许插入/删除时 `dist = n + m - 2·LCS`；本题替换也算一步，所以不能直接套这个公式
- 脚本长度 = `dist` + `M` 的个数（`M` 不花代价），不要以为串长等于距离

### 实操（仓颉）

- **二维数组必须逐行新建**：`Array<Array<Int64>>(n+1, repeat: Array<Int64>(m+1, repeat: 0))` 只复制内层引用，所有行共享同一块内存（改一行等于改全部）；写成 `dp[i] = Array<Int64>(m+1, repeat: 0)` 才是独立行
- 字符比较用 `s1[i-1] == s2[j-1]`（返回 `Byte`，ASCII 下直接比）
- 重建从 `(n, m)` 往回退，优先级 `M` → `S` → `D` → `I`：先看"末字符相等且 `dp[i][j] == dp[i-1][j-1]`"，再依次试其余三条
- 实测：D18-D 的 05 用例（|s1| = |s2| = 1000，10⁶ 个格子）在 judge 里约 319 ms

### 建议（做完 D18-D 之后看）

- 自检：两个单字符不同（`a → b` 是 1 步替换，不是 2 步删除+插入）、完全相同的串（`dist=0`、全是 `M`）、以及重复字符多的串（最优脚本很多，检验去重口径）
- 高频错法：二维表共享内存、边界行忘了初始化、重建时比较顺序搞乱导致脚本对不上样例
- 需要 O(m) 空间时用两行滚动做"只求距离"的版本；一旦要方案，就得回到完整表或额外存回溯信息
