# D17 · 贪心

> 4 个单元，每个单元三段：**学术**（定义/不变量/为什么对）→ **实操**（仓颉写法/边界/实测）→ **建议**（做完对应题目再看）。
> 贪心题的唯一真问题是"为什么这样排/这样选是对的"。本关四道题分别给出四种理由：交换论证（17.1、17.2）、层扩展水位（17.3）、全序关系（17.4）。

## 17.1 区间调度（D17-A）

### 学术

- 问题：在给定区间族里选最多的两两不重叠子集。半开区间 `[l, r)` 兼容的判据是 `r_i ≤ l_j`（端点相接不算重叠）
- **交换论证**：设最优解按右端点排好后第一个区间是 `J`。取所有区间里右端点最小的 `I`，则 `r_I ≤ r_J`；用 `I` 换掉 `J` 后，剩下的区间与 `I` 仍然兼容（因为它们的左端点 ≥ `r_J ≥ r_I`），个数不变。故"存在一个包含 `I` 的最优解"
- 归纳：换掉第一个之后再对剩余问题重复同一论证，得到"按右端点最早结束逐个选"就是最优
- 其余排法都有反例：按左端点升序（一个超长区间会独占全场）、按长度升序（很多短区间被一个中区间挡住）；复杂度 O(n log n)（排序主导）

### 实操（仓颉）

- 存成元组 `(r, l)` 直接 `sort`，第一维就是排序关键字；等价写法是 `sort(iv, by: {x, y => ...})`
- 扫描时维护 `lastRight`（上一个被选区间的右端点），条件写 `l >= lastRight` 就选它；`lastRight` 初值取 `-1`（区间左端点 ≥ 0）
- 别用 `ArrayList` 的 `remove` 去"删掉冲突区间"——那是 O(n²)
- 实测：D17-A 的 05 用例（n = 2×10⁵、坐标到 10⁹）在 judge 里约 614 ms

### 建议（做完 D17-A 之后看）

- 自检：`(1,3) (3,6)` 必须能同时选（端点相接），`(2,5)` 与 `(2,5)` 只能选一个
- 想验证贪心对不对：写一个 O(2ⁿ) 的暴力在 n ≤ 10 的随机数据上对拍，比盯着证明看更快
- 换成"每个区间有权重、求最大权独立集"时这个贪心就失效了，那时要上 DP

## 17.2 最少区间覆盖（D17-B）

### 学术

- 问题：用最少的闭区间覆盖 `[S, T]`。把"已经连续覆盖到哪"记成一个水位 `pos`，每步要解决的是"从 pos 继续往前顶"
- **交换论证**：设当前需要覆盖 `pos`，候选是所有权间里 `l ≤ pos` 的那些；取其中右端点最远的 `I`。若某最优解在这步选的是 `J`，则 `r_I ≥ r_J`，用 `I` 换 `J` 之后后续覆盖只会更容易，个数不变。故"每步取伸得最远的那一个"不劣于任何最优解
- 不可行判据：若所有 `l ≤ pos` 的区间右端点都 `< pos`，说明 `pos` 这个点没有任何区间能盖住，永远推进不了
- 复杂度 O(n log n)（按左端点排序）+ O(n)（指针只前进）

### 实操（仓颉）

- 按 `(l, r)` 升序排；扫描时用一个只增不减的指针 `idx`，把 `l ≤ pos` 的区间一次性吃进来并维护"最远右端点" `best`
- 推进写法：`pos = best + 1`（`best` 这个点已经被盖住）；`best < pos` 就输出 `-1`
- `best` 初值取 `pos - 1` 就天然表示"还没有候选"，不用另外开标记
- 实测：D17-B 的 05 用例（n = 2×10⁵、T = 10⁹）在 judge 里约 593 ms

### 建议（做完 D17-B 之后看）

- 高频错法：每轮都从数组头重新扫一遍找候选（O(n²)）；只选"第一个 `l ≤ pos` 的区间"（没取最远，个数会多）
- 自检：`S == T` 单点覆盖（含 `l = r` 的退化区间）、起点没有任何区间能盖住（必须 `-1`）、以及区间完全落在 `[S, T]` 之外
- 题目要求的是"覆盖整段"而不是"覆盖若干点"，所以判断推进用 `pos = best + 1`，不要写成 `pos = best`

## 17.3 跳跃游戏（D17-C）

### 学术

- 把"跳 k 次能到达的下标集合"看成第 k 层，层与层之间是**区间**：若第 k 层是 `[0, curEnd]`，则第 k+1 层是 `[0, far]`，其中 `far = max{ i + a[i] : i ≤ curEnd }`
- **层扩展（水位）**：扫到 `i == curEnd` 说明这一层走完了，必须把水位抬到 `far` 并且步数 +1；因为每层都是区间、且层间的可达性是嵌套的，"抬水位"的次数就是最少跳数
- 断路判据：若某个 `i > far`，说明前面的层最多只能到 `far`，`i` 之后的位置永远到不了，输出 `-1`
- 复杂度 O(n)：每个下标进出一层一次

### 实操（仓颉）

- 三个变量：`steps`、`curEnd`（本跳水位）、`far`（下一跳水位）；一趟 `while (i < n)` 即可
- 计步条件必须带 `i < n - 1`：起点就是终点（n = 1）时步数是 0，不是 1
- 别写"从 i 出发把 i+1..i+a[i] 全部标记一遍"——a[i] 可以到 10⁹，那是 O(Σa) 的写法
- 实测：D17-C 的 05 用例（n = 2×10⁵，前 1/3 是 1–3 的小步、后 2/3 是 0–10⁹ 的大步）在 judge 里约 124 ms

### 建议（做完 D17-C 之后看）

- 自检：`[0]`（输出 0）、`[1,0,0,0]`（输出 -1）、`[2,3,1,1,4]`（输出 2）
- 判断自己有没有退化成 O(n²)：最大用例的 05 里前 1/3 是 3.2 万层的"阶梯"，逐层扫描会直接爆掉
- 同一套水位思路可以解"最多能到哪/最少几步到某点"，是 BFS 的 O(1) 空间版本

## 17.4 拼最大数（D17-D）

### 学术

- 定义 `x ≺ y ⇔ x + y < y + x`（字符串拼接后按字典序比较）。要能排序，必须验证它是**全序**
- 反对称：`x + y < y + x` 与 `y + x < x + y` 恰好互斥；自反性显然。**传递性**可证：把 `x+y` 与 `y+x` 的比较看成"`x` 与 `y` 无限重复串"的字典序比较，重复串的比较是良定义的字典序，因此传递
- 于是"按 `≻` 降序排列后拼接"就是最大拼接：若相邻两项顺序颠倒会更小，而任何逆序对都能通过相邻交换消除，故该排列全局最优
- 复杂度 O(n log n) 次比较，每次比较 O(len)；长度上界 20 位，可放心比较

### 实操（仓颉）

- 比较器写成 `sort(parts, by: {x, y => if (x + y > y + x) { Ordering.LT } else if (...) { Ordering.GT } else { Ordering.EQ } })`
  —— `sort` 的结果是"比较器给出的自然序"，返回 `LT` 的元素排在**前面**，所以"大的在前"要返回 `LT`
- 数字串可能有 20 位（超过 `Int64` 上限 9.2×10¹⁸），全程按字符串处理，不要 `Int64.parse`
- 拼完用 `s[k..s.size]` 切片去掉前导零（`s[i]` 返回 `Byte`，与 `b'0'` 比较）；全零时单独输出 `0`
- 实测：D17-D 的 05 用例（n = 10⁵、每个 20 位）在 judge 里约 581 ms

### 建议（做完 D17-D 之后看）

- 自检：`3 30 34 → 34330`（比较器写反会得到 `30334`，这是最容易发现方向错误的样例）、`0 0 0 0 → 0`、以及带前导零的串（`007`）
- 直接比 `x < y` 是错的：`830` 与 `8308` 字典序判定会给出 `8308308`，而正确答案是 `8308830`
- 全零边界单独处理：`0000` 去前导零后是空串，必须补一个 `0` 输出
