# D7 · 二分查找

> 4 个单元，每个单元三段：**学术**（定义/不变量/为什么对）→ **实操**（仓颉写法/边界/实测）→ **建议**（做完对应题目再看）。
> 本关的核心只有一句：**把答案锁在一个区间里，每轮砍掉一半**。难的不是循环，是不变量和边界。

## 7.1 lower/upper_bound（D7-A）

### 学术

- 不变量：把搜索范围写成 `[lo, hi)`，循环中始终保证"答案在区间内"，`lo == hi` 时区间退化成答案
- `lower_bound(x)` = 第一个 ≥ x 的下标；`upper_bound(x)` = 第一个 > x 的下标；两者只差比较符 `<` 与 `<=`
- 推论：`count = ub − lb`，且 `lb == ub` 恰好刻画"x 不存在"，不需要额外判断
- 每轮区间长度至少减半 ⇒ Θ(log n)；n = 2×10⁵ 时最多 18 轮，q = 10⁵ 次查询约 2×10⁶ 次比较

### 实操（仓颉）

- 数组用 `Array<Int64>(n, repeat: 0)`；两行输入靠 `readln()` + `trimAscii().split(" ", removeEmpty: true)`
- 中点写 `mid = lo + (hi - lo) / 2`，保证 `mid < hi`，天然不越界
- `hi` 初值取 `n`（不是 `n - 1`），配 `while (lo < hi)`；一旦改成 `while (lo <= hi)` 就必须配 `mid ± 1`，两套约定不能混用
- 输出 10⁵ 行用 `StringBuilder` 攒完一次 `print`；实测 05（n=2×10⁵、q=10⁵）在 judge 里 389 ms

### 建议（做完 D7-A 之后看）

- 只在"有序"或"判定单调"的数据上二分；有重复又想要"任意一个"时也应当用 lb/ub，而不是靠第一次命中
- 最高频错法：`while (lo < hi)` 里写 `lo = mid` —— 区间没变小，直接死循环
- 一行自检：`n = 1` 时分别查 命中值 / 更小值 / 更大值，三种输出一次看完

## 7.2 二分答案·最大化（D7-B）

### 学术

- 二分答案的前提是谓词单调：`check(W)` 可行 ⇒ 任何更小的 W 也可行，于是"可行集合"是一个前缀
- 本题的 `check(W)` 是贪心而非构造：从左往右累加，一凑够 W 就切一刀，数出最多能切几段 `m(W)`
- 正确性：序列元素全为正，把相邻段合并只会让段和变大 ⇒ `m(W) ≥ k` 时一定存在"恰好 k 段且每段 ≥ W"的切法
- 上界可以收紧：k 段每段都 ≥ W 时 `Σ ≥ k·W`，故 `W > Σ/k` 必不可行；复杂度 O(n log(Σ/k))

### 实操（仓颉）

- 第一行两个数用一次 `split(" ", removeEmpty: true)` 切出来，别用两次 `readln()`
- `check` 的热循环用下标 `while (i < n)`，不要 `for (v in a)`：实测对 `Array<Int64>` 迭代器比下标慢一倍多
- Σ 最大 2×10¹⁴ → 必须 `Int64`；`hi = total / k + 1` 比 `hi = total` 少十几轮
- 实测 05（n=2×10⁵、k=10⁵）282 ms

### 建议（做完 D7-B 之后看）

- 看到"最大化最小值 / 最小化最大值"先写 `check`，再套二分；先想贪心构造通常想不出来
- 最高频错法：把"恰好 k 段"直接当"至少 k 段"，却说不清为什么可以合并 —— 合并的依据是元素为正
- 一行自检：`k = n`（只能每段一个数）与 `k = 1`（整条一段）两个端点各跑一次

## 7.3 旋转数组最小值（D7-C）

### 学术

- 旋转后的数组分成两段，各自非降序，且后段所有元素 ≤ 前段所有元素；"下降点"至多一个，最小值就在它上面
- 判据必须拿 `a[mid]` 与 `a[hi]` 比：`a[mid] > a[hi]` 说明 mid 落在较大的前段，答案在右侧
- `a[mid] < a[hi]` 时 mid 自己可能就是答案，所以收缩写 `hi = mid`，**不能** `mid - 1`
- 重复元素使 `a[mid] == a[hi]` 时判据信息量为 0，只能 `hi -= 1` ⇒ 最坏 O(n)（全相同数组即最坏情形）

### 实操（仓颉）

- 只读两行；`n = 1` 时循环不进入，直接输出 `a[0]`，无需特判
- `hi -= 1` 分支是重复元素的真实代价，不要为了"看起来是 O(log n)"换成别的判据（会漏掉答案）
- 实测 05（n=2×10⁵，最小值的连续段被旋转拆成"开头一段 + 结尾一段"）120 ms

### 建议（做完 D7-C 之后看）

- 本题只要求输出最小值。旋转 + 重复时"最小值的首次下标"没有 O(log n) 的单调判据，硬求下标就会给出错误答案（`大纲.md` 第 4 节第 5 条已把这个口径固定下来）
- 最高频错法：拿 `a[mid]` 与 `a[lo]` 比；或把 `hi = mid` 写成 `hi = mid - 1`
- 一行自检：完全没旋转、只旋转 1 位、全部元素相同，三种数组各跑一次

## 7.4 最小化最大值（D7-D）

### 学术

- 与 7.2 互为反方向：这里求**最小**的可行 W，判定改写成"每个工人工作量都不超过 W 时，最少需要几个人 ≤ k"
- `check(W)` 的贪心是"每人尽量多拿"（累加到再加就超 W 才换人），得到的是最少人数；`a[i] > W` 时直接不可行
- 二分写法：`lo = 0`（不可行下界）、`hi = Σ`（一定可行），`while (lo < hi)` 配 `hi = mid / lo = mid + 1`
- 第二问不用再算一次：`check(W*)` 返回的最少人数就是方案规模；复杂度 O(n log Σ)

### 实操（仓颉）

- `minWorkers` 返回 `Int64`；单个任务超过 W 时返回一个极大值（如 `9223372036854775807`）而不是 `-1`，避免与"1 个人"混淆
- 顺序不能打乱：这是序列切分，不是装箱，`sort` 之后再贪心是错的
- 答案量级 3.34×10¹¹ 已越过 32 位，Σ 与所有中间量用 `Int64`；实测 05（n=2×10⁵、k=1000）324 ms

### 建议（做完 D7-D 之后看）

- 先确认三条约束：连续段、每人至少一个任务、最多 k 人 —— 少一条 `check` 就写错
- 最高频错法：`check` 里忘了"单个任务 > W 直接不可行"，于是把不可能的情况判成 1 段
- 一行自检：造一个 k > n 的用例（工人比任务多），答案应被"最大单任务"卡住
