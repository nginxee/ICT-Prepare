# D2 · 数组与 ArrayList

> 4 个单元，每个单元三段：**学术**（定义/不变量/为什么对）→ **实操**（仓颉写法/边界/实测）→ **建议**（做完对应题目再看）。
> 本关的主题是"**选对载体、写对下标**"：定长 `Array` 与变长 `ArrayList` 的代价完全不同，选错要么越界，要么把 O(n) 写成 O(n²)。

## 2.1 定长数组的逆序与对称统计（D2-A）

### 学术

- 逆序是一个对称置换：位置 i 与 n+1−i 互换。它由 ⌊n/2⌋ 个互不相交的对换组成，所以**最少交换次数就是 ⌊n/2⌋**
- 循环不变量：进入每轮时 `[0,left)` 与 `(right,n)` 已就位；每轮把这区间各缩 1，终止条件 `left ≥ right`
- 终止条件必须是 `left < right` 而不是 `≤`：n 为奇数时中间元素与自己"交换"会多算一次，`swaps` 就偏大
- `same` 统计的是对称位置取值相等的对数，n 为奇数时中点不与自身配对，因此只扫 `i < n−1−i`
- 复杂度：时间 Θ(n)、额外空间 Θ(1)（原地）

### 实操（仓颉）

- 定长数组用 `Array<Int64>(n, repeat: 0)`；`size` 是 Int64，下标也用 Int64，不必转 Int32
- 交换写三步临时变量：`let t = a[i]; a[i] = a[j]; a[j] = t`（别指望库里的 swap）
- 输出 2×10⁵ 个数：`StringBuilder` + `sb.append(v)`，且"第一个数前面不加空格"
- `Array` 是引用类型：`let b = a` 只是别名，改 `b[i]` 就是改 `a[i]`；要独立副本用 `arr.clone()`
- 实测：n=2×10⁵ 的用例 05 在 judge 里约 230 ms

### 建议（做完 D2-A 之后看）

- 适用：长度已知、按下标随机读写；不适用：频繁在中间插入/删除（ArrayList 的中间插入也是 O(n)）
- 最高频错法：循环条件写成 `left <= right`（奇数长度多做一次交换）；`same` 在交换之后才统计（数组已被改掉）
- 自检：n=1、n=4 的回文数组各跑一次，确认 `swaps == ⌊n/2⌋` 且 `same` 等于手算的"对称对相等个数"

## 2.2 保序去重（D2-B）

### 学术

- 保序去重 = 每个等价类（相等的值）只保留**最左代表**；结果序列就是把所有不同值按"首次出现位置"升序排列
- 因此答案是唯一的：设 f(v) 为 v 的首次出现位置，结果 = 按 f(v) 升序的不同值序列
- 本题还要先剔除等于 x 的元素，被删个数 = `n − 保留个数`，两类（等于 x、重复）都要计入
- 复杂度：用哈希记"见过"是期望 Θ(n)；用 `ArrayList.contains` 判重、或边删边扫，都是 Θ(n²)（n=2×10⁵ 时约 4×10¹⁰ 次比较）

### 实操（仓颉）

- `HashMap<Int64, Bool>` 记"见过"：`seen.contains(v)` / `seen.add(v, true)`（没有 `put` / `containsKey`）
- 一趟重建：结果容器只做 `add`（尾插 O(1)），**绝不**在扫描中 `remove(at:)`
- 空结果固定输出 `kept=none`（小写半角），不是空行也不是 `kept=`
- 实测：n=2×10⁵、约 19 万个不同值的用例 05 约 410 ms

### 建议（做完 D2-B 之后看）

- 适用：去重且要保留首次出现顺序；若只要个数或不关心顺序，`HashSet` 更省事
- 最高频错法：一边遍历一边 `remove(at: i)`（删除后下标前移，元素被跳过）；`removed` 只算了重复、漏了等于 x 的
- 自检：全等于 x（应 `kept=none`）、全不重复（`removed` 只等于 x 的个数）、x 一次都不出现，三种各跑一次

## 2.3 切片与循环右移（D2-C）

### 学术

- 右移 r 位 = 把数组切成 `a[n−r..n)` 与 `a[0..n−r)` 两段再拼接；由于位移以 n 为周期，**r = k mod n**
- 拼接后第 i 个元素来自原数组下标 `(i − r) mod n`，因此每个元素恰好出现一次（置换）
- r = 0（k 是 n 的整数倍）时结果与原数组相同；n = 1 时任何 k 都等价于不动，这两个边界必须单独正确
- 复杂度 Θ(n)；"每移一位就把整个数组搬一遍"是 Θ(k·n)，k 到 10⁹ 时不可行

### 实操（仓颉）

- `arr.slice(start, len)` 的**第二个参数是长度**：尾巴是 `a.slice(n-r, r)`，头段是 `a.slice(0, n-r)`
- 本题的 `pre` / `suf` / `sum` 都取原数组，所以不能原地搬动 `a`；用切片拼到一个新的 `ArrayList` 里
- 输出 2×10⁵ 个数（约 2.2 MB）必须用 `StringBuilder` 拼完再 `println` 一次
- 实测：n=2×10⁵、k=123456789 的用例 05 约 250 ms

### 建议（做完 D2-C 之后看）

- 适用：一次性整体位移；若需要反复位移，维护一个偏移量指针，而不是每次都真搬数组
- 最高频错法：把 `slice(start, end)` 当"结束下标"写 → 段长偏短；忘记 `k % n`，把 k 直接当 r 用导致越界
- 自检：k=0、k=n、k=10⁹ 三种各跑一次，其中 k=n 时 `rot` 必须逐字符等于原数组

## 2.4 稳定分区（D2-D）

### 学术

- 稳定性 = 同类元素之间的相对次序不变；分区 = 按谓词（`a < 0`）把集合分成两块
- 关键事实：稳定的两路分区**不能**用"两端对撞交换"实现（对撞会颠倒同类元素的相对次序），只能"分桶后按桶拼接"
- 分区后 `part = 负桶 ++ 非负桶`，两个桶内部都保留原相对顺序，所以结果唯一
- 复杂度 Θ(n)；相邻交换式的稳定分区最坏要 (#负 × #非负) ≈ 10¹⁰ 次交换，n=2×10⁵ 时超时

### 实操（仓颉）

- 两个 `ArrayList<Int64>` 只做尾插，最后先输出负桶、再输出非负桶
- 三个计数在同一趟里做：`v < 0` → neg，`v == 0` → zero，否则 pos；0 归"非负"但不计入 pos
- 把分区封装成结构体方法时，改字段必须声明 `mut func`（`class` 的方法不需要 mut）
- 实测：n=2×10⁵ 的用例 05 约 250 ms

### 建议（做完 D2-D 之后看）

- 适用：按谓词分组且要求保序；不要求稳定时可用两端对撞交换，省掉一个数组
- 最高频错法：用冒泡/插入式相邻交换做稳定分区（必超时）；把 0 算进 `pos`
- 自检：已分区的输入（全负数、全非负数）各跑一次，`part` 必须与原数组逐字符相同
