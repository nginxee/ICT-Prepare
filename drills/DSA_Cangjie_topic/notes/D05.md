# D5 · 链表

> 4 个单元，每个单元三段：**学术**（定义/不变量/为什么对）→ **实操**（仓颉写法/边界/实测）→ **建议**（做完对应题目再看）。
> 本关的统一主题是：链表就是"后继函数"，仓颉没有指针算术，所以链接要么写成 `class + Option`，要么写成 `nxt[]` 下标数组——后者更好判题。

## 5.1 链表表示与遍历（D5-A）

### 学术

- 定义：链表是"值 + 后继"对的集合，后继关系构成一条从 head 出发的有向路径，`-1`（或 null）表示终止
- 数组模拟的实质：把"指针地址"换成"节点下标"，`nxt[i]` 就是 i 的后继；语义与真实指针完全一致，只是地址可枚举
- 不变量：沿 next 走不会重复访问同一节点（无环），所以遍历必然终止；能到达的节点集合未必是全部节点
- 代价：遍历 Θ(L) 时间、Θ(n) 空间；随机访问 Θ(L)——这就是链表相对数组的取舍

### 实操（仓颉）

- `Array<Int64>(n, repeat: -1)` 存 next，`Array<Int64>(n, repeat: 0)` 存值；n ≥ 1 时长度就取 n
- 遍历骨架：`cur = head; while (cur != -1) { ...; cur = nxt[cur] }`，判的是下标合法性，不是"访问过没有"
- 输入里节点下标是打乱的，按输入顺序输出一定错——只能顺着 next 走
- 输出整条链用 `StringBuilder` 拼一次；10⁵ 个值逐个 `println` 会慢
- 实测：n = 2×10⁵ 的 05 用例约 490 ms（其中读入 2×10⁵ 行占大半）

### 建议（做完 D5-A 之后看）

- 题面给的是"下标 + next"就照数组模拟写，不必硬造 `class` + `Option`；两种表示只在"需要动态增删节点"时才有区别
- 遍历前先判 `head == -1`，空链表是最容易漏的分支
- 自检动作：样例 1 若输出 `10 20 30 40`（输入顺序）而不是 `40 10 30 20`，说明根本没走 next

## 5.2 反转单链表（D5-B）

### 学术

- 目标：把后继关系整体反向，新 head 是原 tail，原 head 的 next 变成 `-1`
- 三指针不变式：`prev` 指向已反转段的头、`cur` 指向待反转段的首，且已反转段内每个节点的 next 都指向它的（新）后继
- 为什么对：每步先保存 `cur` 的原 next，再把 `cur` 的 next 指向 `prev`，然后 `prev = cur`、`cur = 保存值`——不变量每轮恢复，循环结束时 `prev` 就是新 head
- 代价：Θ(n) 时间、Θ(1) 额外空间（输入数组本身不算）

### 实操（仓颉）

- 顺序不能错：先 `nxtSave = nxt[cur]`，再 `nxt[cur] = prev`；反了就丢失剩余链
- 循环到 `cur == -1` 结束，收尾 `newHead = prev`
- 判题除了值序列还看反转后的 `next` 数组，所以"把值倒序填回原下标"一定错
- 值全相同的用例里值序列没有信息量，只有 `next` 能判对错
- 实测：n = 2×10⁵ 的 05 用例约 611 ms

### 建议（做完 D5-B 之后看）

- 反转是"原地改链接"的范式；递归版看着短，但 10⁵ 层深每层还压两个指针，比赛用迭代
- 值相等不代表节点相同：判题靠下标，不要用值去去重或判断"是不是同一个节点"
- 自检动作：n = 1 应输出 `next=-1`；n = 2 应输出 `next=-1 0`（原 head 变尾、原尾变头）

## 5.3 合并有序链表（D5-C）

### 学术

- 归并：两链各自有序，每次取两个当前节点中较小者接到结果链尾，可归纳证明结果有序且不丢节点
- 并列规则属于"规格"而非"实现细节"：值相等时取链表 1 的节点，输出才唯一（否则同一多重集有多种合法链接）
- 下标空间：合并后一条链跨两条输入链，要给链表 2 的节点加偏移 n1 才能用一张 next 表表示
- 代价：Θ(n1+n2) 时间与空间，不产生额外 log 因子

### 实操（仓颉）

- 结果 next 开**新表** `Array<Int64>(n1+n2, repeat: -1)`，不要在原地改两条输入链的 next
- 归并循环条件 `cur1 >= 0 || cur2 >= 0`；某条链先走完就把另一半整段接上
- 取左条件写成 `!(val2 < val1)`（即相等取链表 1）；这一行直接决定"两链全同值"用例的答案
- 实测：n1 = n2 = 10⁵ 的 05 用例约 578 ms

### 建议（做完 D5-C 之后看）

- 归并稳定与否只由"相等时取哪边"决定；动手写比较之前先把这条约定确定下来
- 不要用 `sort` 把值排一遍再回填：值对了，`next` 全错
- 自检动作：两链全为同一个值的用例，`next` 应形如 `1 2 3 4 5 6 -1`，即链表 1 的节点全部先接上

## 5.4 快慢指针（D5-D）

### 学术

- 判环（Floyd）：slow 每步 1、fast 每步 2；若存在环，fast 先入环并在环内每轮追近 1，必与 slow 相遇；fast 走到终止则无环
- 求入口：相遇后把一个指针移回 head，两者都改成每步 1，再次相遇处就是入口（head 到入口的距离与相遇点到入口的距离模环长同余）
- 链上不同节点数 = 入口前步数 mu + 环长 lambda；lambda 从入口出发绕一圈数回来
- 左中点：fast 不能再走两步时 slow 停在 0 基下标 `(L-1)/2`；有环时该定义失效
- 代价：Θ(n) 时间、Θ(1) 额外空间

### 实操（仓颉）

- 判环循环条件要同时判 `fast != -1` 与 `nxt[fast] != -1`，少一半就会多走一步或越界
- 自环（n = 1、`nxt[0] = 0`）第一轮就该判出环，是必测边界
- 输出的是节点下标；节点值只有三五种且大量重复，按值猜答案没有出路
- 实测：n = 2×10⁵（前缀 96000 + 环长 104000）的 05 用例约 388 ms

### 建议（做完 D5-D 之后看）

- 判环优先用 Floyd（O(1) 空间）；只有还需要"哪些节点在环上"时才开访问标记数组
- 别用"每个节点各自往后走看是否重合"判环：那是 O(n²)，大用例必超时
- 自检动作：单节点自环应输出 `len=1 / mid=-1 / cycle=1 / entry=0`；偶数长无环链的 mid 应落在靠前的一半
