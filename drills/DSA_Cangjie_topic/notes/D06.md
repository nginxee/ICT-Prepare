# D6 · 排序

> 4 个单元，每个单元三段：**学术**（定义/不变量/为什么对）→ **实操**（仓颉写法/边界/实测）→ **建议**（做完对应题目再看）。
> 本关的统一主题是：比较器写错是最大失分点——排序算法库里都有，你要决定的只是"两个元素谁在前"。

## 6.1 比较器排序（D6-A）

### 学术

- 排序要求比较关系是**全序**：反对称、传递、任意两个元素可比；比较器不满足传递性时，任何算法的结果都无法预期
- `sort(by:)` 的语义：比较器返回 `Ordering.LT` 的元素排到前面；返回"自然序"（`x > y` ⇒ `GT`）得到升序
- 稳定性：相等元素的相对次序在排序后保持不变；比较排序不自动保证稳定，需要显式要求
- 代价：Θ(n log n) 次比较、Θ(1) 额外空间（原地排序）

### 实操（仓颉）

- 三种写法：`sort(a)` 升序、`sort(a, descending: true)` 降序、`sort(a, by: {x, y => ...})` 自定义
- `by:` 是**命名参数**；比较器返回 `Ordering`，三路 `if/else` 写全（LT / GT / EQ），不要用整数减法
- 排序会改原数组：要保留原序就 `clone()`，四行结果各用一份
- 求"原始下标序列"用 `ArrayList<(Int64, Int64)>` 加 `stable: true`；相等元素保序，下标序列因此唯一
- 实测：n = 10⁵ 的 05 用例（四次排序 + 3.7 MB 输出）约 679 ms

### 建议（做完 D6-A 之后看）

- 写比较器第一件事：确定升序还是降序，然后只改 LT / GT 的方向，其余结构一个字不动
- 多键比较一律写成"第一键不等就返回、相等才看第二键"的 if-else 链，别用减法合成一个键
- 自检动作：同一组数据用 `descending: true` 与自己写的反写比较器各跑一次，结果必须完全一致

## 6.2 多键排序（D6-B）

### 学术

- 字典序：按键序列逐位比较，第一个不等的键决定次序——多键排序本质就是对元组做字典序
- 正确性：每对元素都有确定次序，且由字典序给出（满足全序），所以排序结果唯一
- 键的方向可以混搭：第一键降序、第二键升序仍是合法全序，只要方向固定
- 代价：Θ(n log n)；比"先按次键排一遍、再按主键稳定排一遍"更省一趟

### 实操（仓颉）

- 元素用 `ArrayList<(String, Int64)>`，取 `x[0]` / `x[1]`
- 第一键降序：`x[1] > y[1]` 时返回 `Ordering.LT`；第二键升序：`x[0] < y[0]` 返回 `LT`
- 两个键放进同一个 if-else 链；分两趟 `sort` 会把第一趟的结果打乱
- 姓名是纯小写 ASCII，`String` 的 `<` / `>` 直接就是字典序（短前缀排在前）
- 实测：n = 10⁵ 的 05 用例约 475 ms

### 建议（做完 D6-B 之后看）

- 遇到"主键 + 次键"，先问清次键方向再动手；方向混搭是这类题最高频的错法
- 完全相同的两条记录之间不分先后，题面写清"按原样输出"即可，不必再造第三个键
- 自检动作：造一组"主键全相同"的数据跑一遍，输出应严格按次键有序

## 6.3 计数排序（D6-C）

### 学术

- 比较排序的下界是 Ω(n log n)；计数排序用"值域"换时间，达到 Θ(n+V)
- 适用条件：键是非负整数且 V 与 n 同量级；V 远大于 n 时桶数组本身就是负担
- 正确性：计数表就是"每个值出现多少次"的直方图，按值从小到大展开即为有序序列
- 代价：Θ(n+V) 时间、Θ(V) 空间，与 n log n 无关

### 实操（仓颉）

- `Array<Int64>(V+1, repeat: 0)` 计数；V = 10⁶ 时约 8 MB，可以放心开
- 不同值个数在同一趟桶扫描里数出来（`cnt[v] > 0`）
- 输出按桶展开、用 `StringBuilder` 一次打印；不要"每个值回原数组再扫一遍"（那是 O(n·V)）
- 实测：n = 2×10⁵、V = 10⁶ 的 05 用例约 270 ms

### 建议（做完 D6-C 之后看）

- 看到"值域很小"（分数 0-100、年龄、月份）先想计数排序；看到 `aᵢ ≤ 10⁹` 就别开桶
- 需要"同值按键的原始次序"时，计数排序要做前缀和式的稳定版本；本题不需要
- 自检动作：n = 1 且取到上界 10⁶，输出应为 `distinct=1`，`sorted=` 就是该值本身

## 6.4 词频 Top-K（D6-D）

### 学术

- 问题 = 聚合（频次）+ 定序（多键全序）+ 截断（取前 k 个）
- 哈希表只保证查找均摊 O(1)，**不保证遍历次序**；任何依赖遍历序的输出都不是确定的
- 定序键要让任意两个不同单词可比：(次数降序, 单词升序) 是全序，所以输出唯一
- 代价：Θ(n) 聚合 + Θ(m log m) 排序（m 为不同单词数）；改用大小 k 的堆可降到 Θ(n + m log k)

### 实操（仓颉）

- `HashMap<String, Int64>` 计数：`freq[w] = (freq.get(w) ?? 0) + 1`
- 收集成 `ArrayList<(String, Int64)>` 再排序；遍历顺序不稳定，不能直接输出
- 截断先算 `min(k, 不同单词数)` 再循环，避免越界
- 并列时字典序兜底必须写进同一个比较器，否则同频词的次序由哈希决定
- 实测：n = 2×10⁵、5000 个不同词、k = 1000 的 05 用例约 532 ms

### 建议（做完 D6-D 之后看）

- 凡是"哈希 + 按某种顺序输出"，收集、排序这两步一步都不能省
- m 远小于 n 时排序成本可忽略；只有 m 很大而 k 很小时才值得上小顶堆
- 自检动作：造一组"所有单词同频"的数据，输出应严格按单词字典序遍历
