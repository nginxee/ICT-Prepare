# D11 · 递归与分治

> 4 个单元，每个单元三段：**学术**（定义/不变量/为什么对）→ **实操**（仓颉写法/边界/实测）→ **建议**（做完对应题目再看）。
> 本关两条主线：递归要有**出口**（否则是指数爆炸或无限下降），分治要能说清**跨段代价怎么一次结清**。

## 11.1 递归三要素（D11-A）

### 学术

- 递归 = 出口 + 递推 + 结构归纳：出口给出基例，递推把规模 n 的问题化为更小的同类问题，归纳保证所有规模都成立
- 朴素 `fib(n) = fib(n-1) + fib(n-2)` 的递归树是二叉展开，T(n) ≈ 1.618ⁿ，n = 45 已约 10⁹ 次调用 —— 不是慢，是**算不完**
- 记忆化把"重复子问题"折叠成一次：同规模只算一次，T(n) = Θ(n)
- Int64 上界 9.22×10¹⁸；`20! = 2432902008176640000`、`F(90) = 2880067194370816120` 都在界内，但都远超 32 位
- 递归深度 = 调用链长度；深度取决于问题结构（阶乘 m ≤ 20、斐波那契 n ≤ 90），不是规模上界 k

### 实操（仓颉）

- 阶乘出口写 `if (m <= 1) { return 1 }`，一次覆盖 `0!` 与 `1!`
- 记忆化用 `Array<Int64>(92, repeat: 0)`，用 0 表示"没算过"；`fib` 里先查表再递归
- 数组和用**迭代**：深度等于 k（2×10⁵ 层），没必要拿调用栈去换这一行代码
- 读入是"第一行三个数 + 第二行一堆数"，两行都 `trimAscii().split(" ")` 后逐个 `Int64.parse`
- 实测：k=2×10⁵ 的 05 用例在 judge 里约 118 ms

### 建议（做完 D11-A 之后看）

- 递归只写在"子问题不重复"或"能加表"的地方；重复子问题一定上表或改迭代
- 最高频错法：`int` 装阶乘/斐波那契；另一个是把出口写成 `m == 0`，漏掉 `1!`
- 自检动作：n = 90 必须秒出 `2880067194370816120`；m = 1 必须输出 `fact=1`

## 11.2 归并排序（D11-B）

### 学术

- 递推式 `T(n) = 2T(n/2) + Θ(n)` ⇒ `T(n) = Θ(n log n)`；每层总代价 Θ(n)，层数 Θ(log n)
- **稳定性来自 merge 的取左条件**：左边 `a[i] <= a[j]` 时取左，相等元素就不会被右半边"抢到前面"，相对次序因此守恒；写成 `<` 立刻变不稳定
- 稳定 ⇔ 并列元素在新数组里的相对下标仍递增；用"下标数组排序"可以让这件事直接变成可判的输出
- 空间 Θ(n)（临时数组），递归深度 Θ(log n)（n = 2×10⁵ 时约 18 层）
- 正确性依据：merge 前两半各自有序，merge 每步取两者较小者即保持有序；相等时取左 ⇒ 稳定

### 实操（仓颉）

- 临时数组只开一次，merge 结果先写临时数组、再整段搬回原数组，避免每层都 `new`
- 对**下标数组**排序：`perm` 初值 `0..n-1`，比较时取 `a[perm[i]]`，最后 `a[perm[i]]` 就是排序结果
- 骨架：`while (i < mid && j < hi) { if (a[perm[i]] <= a[perm[j]]) 取左 else 取右 }`，再补两段剩余
- 实测：n=2×10⁵、输出 2.4 MB 的 05 用例在 judge 里约 763 ms

### 建议（做完 D11-B 之后看）

- 判断自己写对没写对，只看一句：并列为真时你先取哪边。取左 = 稳定，取右 = 不稳定
- 最高频错法：`a[i] < a[j]` 少一个等号（样例 idx 行会错），或用 `ArrayList.insert` 插排（O(n²)）
- 自检动作：全相同数组（如 10 个 `7`）的 idx 行必须正好是 `1 2 3 … 10`

## 11.3 快速幂（D11-C）

### 学术

- 指数二进制分解：`a^b = ∏_{k: b 的第 k 位为 1} a^(2^k)`，因此把指数不断除 2、底数不断自乘即可，Θ(log b) 约 60 步
- 模运算与乘法同态：`(xy) mod m = ((x mod m)·(y mod m)) mod m`，所以可以**每步取模**
- 溢出边界：`m ≤ 2×10⁹` ⇒ 先取模再相乘时乘积 ≤ 4×10¹⁸ < 9.22×10¹⁸，Int64 够用，不需要更宽的整数
- 基例是空积约定：`a^0 = 1`，落到模上就是 `1 mod m`（m = 1 时为 0）
- 正确性依据：模同态 + 指数二进制唯一分解，两条合起来保证每步化简不改变最终余数

### 实操（仓颉）

- 骨架：`res = 1 % m; base = a % m; while (e > 0) { if (e % 2 == 1) res = res * base % m; base = base * base % m; e = e / 2 }`
- `1 % m` 而不是直接写 1，一次覆盖 `m = 1` 的边界
- `a % m` 也要先做：a 可能大于 m，先归约把所有中间量压进安全区间
- q 行输入用循环 `readln()`，输出用 `StringBuilder` 一次 `print`
- 实测：q=10⁵、b 到 10¹⁸ 的 05 用例在 judge 里约 473 ms

### 建议（做完 D11-C 之后看）

- 只在最后取模是错的：`a^b` 几步就溢出成负数，之后怎么取模都救不回来
- 递归版（`pow(a,b/2)²`）和迭代版等价，深度只有 60 层；比赛里迭代更快也更不容易栈出错
- 自检动作：`m = 1` 必须输出 `0`；`b = 0` 必须输出 `1`（`0^0` 也算 1）

## 11.4 逆序对计数（D11-D）

### 学术

- 分治计数：`总逆序对 = 左半内部 + 右半内部 + 跨两半`，前两项递归，第三项在 merge 时一次结清
- 跨段结清的判据：merge 里要取右半的 `a[j]`，说明左半从 `i` 到 `mid-1` 的每个元素都大于它，一次加 `mid - i`
- 相等**不算**逆序（要求严格大于），所以取左条件写成 `a[i] <= a[j]`
- 答案上界 `n(n-1)/2 = 19999900000`，是 32 位上限的 9 倍多，必须 Int64
- 复杂度 Θ(n log n)，与归并排序同阶；计数不需要额外一趟，merge 顺手加即可

### 实操（仓颉）

- 递归函数返回 `Int64` 的计数：`var cnt = msort(lo, mid) + msort(mid, hi)`，再在 merge 里 `cnt += mid - i`
- 累加与返回类型都写 `Int64`，别让编译器从字面量推成小类型
- merge 结束后整段回写原数组，保证上一层看到的是有序半区
- 实测：n=2×10⁵ 的 05 用例在 judge 里约 567 ms（答案约 10¹⁰ 量级）

### 建议（做完 D11-D 之后看）

- 暴力枚举是 2×10¹⁰ 次比较，5 秒也不够；这题的唯一可用骨架就是归并
- 最高频错法：用 32 位累加。n = 10⁵ 的降序输入答案 4999950000，会溢出成负数
- 自检动作：完全降序应得 `n(n-1)/2`，全相同应得 `0`，这两个极端能同时验出"方向错"和"相等算错"
