# D15 · 最短路与拓扑排序

> 4 个单元，每个单元三段：**学术**（定义/不变量/为什么对）→ **实操**（仓颉写法/边界/实测）→ **建议**（做完对应题目再看）。
> 前两题（D15-A/B）都要用 D13 手写的堆；后两题（C/D）是 BFS 与拓扑序 DP。

## 15.1 Dijkstra（非负边权）（D15-A）

### 学术

- **非负权才能贪心**：所有边权 ≥ 0 时，"当前 `dist` 最小且未定型"的点已经定型——任何绕路都要多经过若干条非负边，只会更长
- 反例：一旦存在负权边，这个点还可能被后面的负边改小，贪心立刻失效（那时要用 Bellman-Ford）
- 不变量：已定型集合 S 内的 `dist` 就是最终最短路；每次松弛 `nd = d + w` 只在更优时更新
- 代价：堆优化 O(m log m)（懒删除下堆条目 ≤ 2m）；朴素"每轮线性扫 dist 找最小"是 O(n²)

### 实操（仓颉）

- 仓颉没有 `PriorityQueue`：手写堆存 `(距离, 顶点)`，用两个平行 `Array<Int64>`
- **懒删除**：松弛成功就 push 一条新条目，弹出时 `if (d > dist[v]) { continue }` 跳过过期项；不要试图修改堆内已有元素的键
- `dist` 初值 `-1` 表示"未访问/不可达"；0 权边合法，所以不能拿 0 当哨兵
- 邻接表可用链式前向星（`head`/`to`/`wt`/`nxt`）省掉 10⁵ 个内层 `ArrayList`，05 用例从 1.43 s 降到 1.02 s
- 实测：D15-A 的 05（n = 10⁵、m = 2×10⁵、w ∈ [0, 10⁹]）在 judge 里约 1.0 s

### 建议（做完 D15-A 之后看）

- 规模判据：n = 10⁵ 时朴素 O(n²) = 10¹⁰ 次比较，5 秒绝无可能；只有 n ≤ 5000 左右才轮得到朴素写法
- 自检：跑一遍 04 用例（0 权边 + 重边 + 3×10⁹ 的距离），能同时验出"用 0 当哨兵"和"32 位溢出"两类错
- 有负权边就别改这一步的代码，换算法；Dijkstra 的贪心前提是"边权非负"，不是"无环"

## 15.2 拓扑排序（D15-B）

### 学术

- DAG ⇔ 存在拓扑序；"入度为 0"是"这个点此刻可以输出"的充要条件
- Kahn：反复取零入度点输出，并把它的出边删掉（邻居入度减一），谁的入度降到 0 谁就可选
- 字典序最小 ⇒ 待选集合必须能取最小 ⇒ **小顶堆**；FIFO 队列只能给出某个拓扑序，给不出最小的那个
- 判环：最后输出的点数 < n ⇒ 剩下的点互相锁死；自环也算环
- 代价：O((n + m) log n)

### 实操（仓颉）

- `indeg` 数组 + 链式前向星；初始化时把所有零入度点入堆
- 每弹一个点，沿出边 `indeg[u] -= 1`，降到 0 就入堆（堆用挖坑上浮/下沉）
- 自环 `u → u` 让 `indeg[u]` 永远不会归零，程序自然落到 `cycle`
- 实测：D15-B 的 05（n = 10⁵、m = 2×10⁵ 的 DAG）约 750 ms

### 建议（做完 D15-B 之后看）

- 题目要"任意拓扑序"用普通队列就够；要"字典序最小"才上堆——多写一个堆换确定性，很值
- 自检：`1→2, 5→3` 这种两点图，正确答案是 `1 2 4 5 3`；如果得到 `1 4 5 2 3`，说明你用的是 FIFO

## 15.3 无权图单源最短路（D15-C）

### 学术

- 有向图只加**单向**边："1 能到 2"不代表"2 能到 1"，不可达在本题里是常态
- BFS 层号 = 最短边数，首次访问即定型，之后不再变
- 出队序由"每个点的出边按编号升序遍历"唯一确定，可以作为判定依据
- 代价：O(n + m log m)（含邻接表排序那一步）

### 实操（仓颉）

- `adj[u].add(v)` 只加一个方向（无向图才加两次），建完表 `sort(adj[i])`
- 队列 + `dist` 初值 `-1`；出队时把点写进出队序数组，最后两行一起输出
- 不可达的点不出现在出队序里，但一定要出现在距离行（`-1`）
- 实测：D15-C 的 05（n = 10⁵、m = 2×10⁵，前 99999 条是有向长链）约 630 ms

### 建议（做完 D15-C 之后看）

- 与 D14-B 的代码骨架完全一样，区别只有三点：有向、只求距离不回溯路径、额外输出出队序。写错方向是最高频的错误
- 自检：起点只有入边时（只给 `1→2`、s = 2），输出必须是 `-1 0 -1` 与 `2`；若你得 `0 1 -1`，就是按无向图建的边

## 15.4 DAG 最长路（关键路径）（D15-D）

### 学术

- 拓扑序上 DP：`f[v]` = 从 1 到 v 的最长距离，每个点的答案只依赖前驱，按拓扑序推进一遍即得
- 最长路**不满足**贪心最优子结构（局部最长 ≠ 全局最长），所以不能套 Dijkstra 那一套
- `ways` 转移：`cand > f[u]` 时重置为 `ways[v]`、`cand == f[u]` 时累加取模；按拓扑序保证所有前驱都已算过
- 代价：O(n + m)；距离量级 10⁵ × 10⁹ = 10¹⁴，必须 `Int64`

### 实操（仓颉）

- 先用 Kahn（普通队列即可）求出拓扑序，再按序做上述松弛
- 条数必须每一步 `% 1000000007`，否则指数增长会把 `Int64` 撑爆
- 不可达：`f[n] < 0` 时输出 `-1` 与 `0`
- 实测：D15-D 的 05（n = 10⁵、m ≈ 2×10⁵，条数 2⁴⁹⁹⁹⁸ 取模）约 540 ms

### 建议（做完 D15-D 之后看）

- 最常见错法是"每步选取最大的出边"（贪心）；反例是两条分支直到汇点才合并，局部最大的那条未必最长
- 自检：04 用例（两条等长最长路）答案必须是 `5000000000` 与 `2`；只输出 `1` 说明"相等要累加"没写
