# D8 · 前缀和与差分

> 4 个单元，每个单元三段：**学术**（定义/不变量/为什么对）→ **实操**（仓颉写法/边界/实测）→ **建议**（做完对应题目再看）。
> 本关是全库重点：**前缀和与差分互为逆算子**，一手"多次查询"、一手"多次修改"。看错方向就是 O(n·q) 超时。

## 8.1 一维前缀和（D8-A）

### 学术

- 定义：`pre[0] = 0`、`pre[i] = a₁ + … + aᵢ`（1 基），长度 n+1
- 不变量：`sum(l..r) = pre[r] − pre[l−1]`；`pre[0] = 0` 正是为 `l = 1` 准备的
- 为什么对：`pre` 是线性算子，差分把 `[1..l−1]` 的前缀整体抵消，只剩 `[l..r]`
- 代价：预处理 Θ(n)、单次查询 Θ(1)、空间 Θ(n)；q 次查询总代价 Θ(n+q)

### 实操（仓颉）

- `Array<Int64>(n + 1, repeat: 0)`，边读边算 `pre[i + 1] = pre[i] + v`，省掉原数组
- 单个区间和最大 2×10¹⁴（n=2×10⁵、|aᵢ|≤10⁹）→ 累计与答案都必须 `Int64`
- 10⁵ 行输出用 `StringBuilder` 拼完一次 `print`，逐行 `println` 会慢一个量级
- 实测 05（n=2×10⁵、q=10⁵）314 ms

### 建议（做完 D8-A 之后看）

- 只在"静态数组 + 多次查询"用；一旦夹着修改就换差分（8.2）或树状数组
- 最高频错法：写成 `pre[r] - pre[l]`（少减一位）；在 `l = 1` 时可能还"看起来对"
- 一行自检：`l = 1`、`l = r = n`、以及一个全负数的区间，三个查询一次跑完

## 8.2 一维差分（D8-B）

### 学术

- **前缀和与差分互为逆算子**：差分 `d[i] = a[i] − a[i−1]`（`d[1] = a[1]`）的前缀和还原出 `a`；反过来，对 `a` 做前缀和再对结果做差分也回到 `a`。所以"求前缀和"与"求差分"是可以互相推导的一对
- 于是"区间加"在差分域里只改两点：`d[l] += x`、`d[r+1] −= x`
- 正确性：两点修改后做前缀和，`[l..r]` 内每点都多 x，`r+1` 起被减回去
- 代价：单次修改 Θ(1)、总体一次还原 Θ(n)；q 次修改 + 还原 = Θ(n+q)

### 实操（仓颉）

- 差分数组开 `n + 2`：`r = n` 时 `d[n+1]` 必须有位置吃这个减法
- 可以先把初值读进 `diff`，再用一趟 `diff[i] = diff[i] - diff[i-1]` 原地转成差分
- 输出 n 个数：数字间一个空格，最后不加空格；实测 05（n=2×10⁵、q=10⁵）378 ms

### 建议（做完 D8-B 之后看）

- 题型对照记牢：**多次查询区间和 → 前缀和；多次修改区间 → 差分；边改边查 → 树状数组**（不在本课范围）
- 最高频错法：写 `d[r] -= x`（区间少一格）；小数据察觉不到，大数据全错
- 一行自检：`n = 1` 且唯一操作 `l = r = 1`，再测一个 `r = n` 的全区间加法

## 8.3 二维前缀和（D8-C）

### 学术

- 定义：`pre[i][j]` = 前 i 行、前 j 列组成的矩形和，行列都从 1 起，第 0 行/列全 0
- 递推：`pre[i][j] = a[i][j] + pre[i−1][j] + pre[i][j−1] − pre[i−1][j−1]`
- **二维容斥四符号**：`S = pre[r2][c2] − pre[r1−1][c2] − pre[r2][c1−1] + pre[r1−1][c1−1]` —— 减掉上方与左方两块，再把被减两次的左上角加回来
- 它同时是"二维差分"的对偶：二维区间加也是四符号、符号全反；这正是"前缀和与差分互为逆算子"在二维的形式
- 代价 Θ(nm) 预处理 + Θ(1)/次查询

### 实操（仓颉）

- 用一维打平 `Array<Int64>((n + 1) * (m + 1), repeat: 0)`，下标 `i * (m + 1) + j`：既快又不用处理嵌套集合
- 读矩阵每行 `split(" ", removeEmpty: true)` 后按列号自增；行列 1 基使得 `r1 = 1` 时不需要特判
- 10⁶ 格 × 10⁴ 量级 = 10¹⁰ → 前缀数组必须 `Int64`；实测 05（1000×1000 + q=10⁵，输入 6.2 MB）623 ms

### 建议（做完 D8-C 之后看）

- 先在纸上画 3×3 把四个符号各写一遍，再落代码；正数数据上少一个符号也可能"答案看着合理"，负数立刻暴露
- 最高频错法：漏掉 `+ pre[r1−1][c1−1]`
- 一行自检：整张矩形（应等于全部元素和）、单格、`n = 1` 的单行三种查询

## 8.4 大规模差分（D8-D）

### 学术

- n = 10⁶、q = 2×10⁵ 时：差分 Θ(n+q) 与逐点模拟 Θ(n·q)=2×10¹¹ 差五个数量级，这就是"规模决定做法"
- 还原时不存新数组：边走前缀和边维护"总和 / 最大值 / 负数个数"，空间只需一个差分数组
- "第一次出现"的语义靠严格大于更新（`cur > mx` 才更新下标），不要用 `>=`
- 溢出边界：单格 ≤ 9 + q·|x| ≈ 2×10¹¹，总和 ≤ 2×10¹⁷，都已越过 32 位 ⇒ 全部 `Int64`

### 实操（仓颉）

- `Array<Int64>(n + 2, repeat: 0)` 一次开好；10⁶ 个初值放在一行里读，别拆成 n 行
- q 行操作各三个数，用 `split(" ", removeEmpty: true)` 切；下标 l、r 直接用，不需要减 1（差分 1 基）
- 实测 05（n=10⁶、q=2×10⁵）630 ms；同规模纯读入约 300 ms，说明瓶颈在 I/O 而不在算法

### 建议（做完 D8-D 之后看）

- n 再涨一个数量级（10⁷）就不要用数组了，改成用 map 存"事件点"，按坐标排序后扫
- 最高频错法：统计量（总和）用 `Int32`/`Int`，被静默截断成负数，样例还能过
- 一行自检：造 q 条全区间 `+10⁶` 的操作，手算总和应为 `n × q × 10⁶` 量级，与输出对齐
