# D1 · 规模、复杂度与 Int64

> 4 个单元，每个单元三段：**学术**（定义/不变量/为什么对）→ **实操**（仓颉写法/边界/实测）→ **建议**（做完对应题目再看）。
> 本关不教算法，教的是"先看 n，再想复杂度"：同一道题用 O(n²) 也写得出，只是过不了 05 用例。

## 1.1 一趟扫描的四个统计量（D1-A）

### 学术

- 求和的结合律：`(((a₁+a₂)+a₃)+…)` 与任意括号方式结果相同，所以可以边读边累加
- 极值、计数与求和互不干扰，因此四个量能在**同一趟**里维护（这是"线性扫描"的典型形态）
- 复杂度的判据不是"代码长短"，而是**访问次数**：n=2×10⁵ 时嵌套循环约 4×10¹⁰ 次比较，5 秒不可能完成
- Int64 上界 9.22×10¹⁸；本题最大和 2×10⁵ × 10⁹ = 2×10¹⁴，安全

### 实操（仓颉）

- 读入：`getStdIn().readln().getOrThrow()` 取两行，第二行 `trimAscii().split(" ")` 后逐个 `Int64.parse`
- 极值初值取**第一个元素**，不要取 0（元素可能全为负）
- `split(" ")` 在连续空格处产生空串，记得 `if (p.size == 0) { continue }`
- 实测：n=2×10⁵ 的用例 05 在 judge 里约 100 ms

### 建议（做完 D1-A 之后看）

- 先写"能过样例"的版本，再故意把自己写的双层循环放到 05 上跑一次，亲眼看到超时——比背复杂度公式有用
- 下标一律想清楚是 0 基还是 1 基，题面要求 1 基输出时在打印处 +1，不要在循环里混着改

## 1.2 平方和与整数均值（D1-B）

### 学术

- 平方和的量级是 n·(10⁹)²=10²³，**任何 64 位类型都装不下**；题目因此给出 `Σaᵢ² ≤ 9×10¹⁸` 的保证
- 整数除法是向零截断（`-7/2 = -3`），不是向下取整（`-4`）；只有被除数非负时两者才一致
- `sumsq/n` 非负，所以这里的截断等于向下取整，可以直接当比较基准

### 实操（仓颉）

- `a * a` 必须两个操作数都是 `Int64`，否则会先按小类型算再溢出
- `avg` 直接写 `sum / Int64(n)`，仓颉的 `/` 已是向零截断，别再自己 `floor`
- 实测：n=2×10⁵ 的 05 用例约 150 ms

### 建议（做完 D1-B 之后看）

- 凡是"先平方/先相乘再累加"的题，先估量级：`n × 单项最大值`，超过 9.2×10¹⁸ 就必须改题面给保证或改用别的统计量
- 本题的 `big` 是"用整数均值当阈值"，它考的是**先算完再比较**，不是边读边比——两种写法只能有一种正确

## 1.3 首次、末次与出现次数（D1-C）

### 学术

- "不存在"要用能区分于合法值的哨兵：下标用 `-1`，计数用 `0`
- 出现位置是有序序列 p₁<…<p_k，`maxgap = max(pᵢ₊₁−pᵢ−1)` 只依赖相邻两项，因此一趟扫描即可
- k ≤ 1 时 maxgap 定义为 0：把"不足两次"作为独立边界处理，避免出现"空集 max"的定义问题

### 实操（仓颉）

- 位置计数推荐 `for (i in 0..n)` 里用 `i + 1` 当 1 基下标，别另开一个变量手加
- 四个量在同一趟里更新：`if (v == x) { if (first == -1) { first = i+1 }; if (last != -1) { gap = max(gap, i+1-last-1) }; last = i+1; count += 1 }`
- 实测：n=2×10⁵ 的 05 用例约 95 ms

### 建议（做完 D1-C 之后看）

- 边界先想三件事：一个都没有、只出现一次、全部都是 x——这三类覆盖了本题所有易错点
- 若题目改成"求最大值的位置"，把哨兵改成 `-1` 的同时记得**初值不能取 0**

## 1.4 最长平台（D1-D）

### 学术

- "相邻且相等"是一段连续的等价块：块内所有元素相等，块与块之间必不相等
- 只需在**块边界**（`a[i] != a[i-1]`）结算上一块，因此全程一趟、无回溯
- 并列取最靠前：更新条件写严格的 `runLen > best`（不是 `>=`），语义直接落在比较符上
- n=10⁶ 时 O(n²) 约 10¹² 次比较，25 秒量级，必然超时

### 实操（仓颉）

- 10⁶ 个数是**一整行**（约 3.9 MB），`readln()` 一次读完再 `split(" ")`，不要在循环里做字符串拼接
- 维护两组变量：`runLen/runStart` 与 `best/bestStart/bestVal`；每读入一个元素就与当前块比较
- 最后一块不用特判：每次加入元素后都立刻比较过 `runLen` 与 `best`
- 实测：n=10⁶ 的 05 用例在 judge 里约 320 ms

### 建议（做完 D1-D 之后看）

- 这类"最长连续段"的题，最容易写成双层循环（内层往后数相同元素）；判断标准只有一个：**有没有回头访问已经看过的下标**
- 平台题还能顺手改成"最长递增段/最长交替段"，只要把 `a[i] == a[i-1]` 换成对应的相邻关系即可，骨架完全不用改
