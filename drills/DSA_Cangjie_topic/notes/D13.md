# D13 · 堆与优先队列

> 4 个单元，每个单元三段：**学术**（定义/不变量/为什么对）→ **实操**（仓颉写法/边界/实测）→ **建议**（做完对应题目再看）。
> 仓颉标准库没有 `PriorityQueue`，这一关的堆全部手写；它也是 D15-A Dijkstra 的前置。

## 13.1 手写最小堆（D13-A）

### 学术

- 定义：完全二叉树用**数组按下标**存；0 基下父 `(i-1)/2`、左 `2i+1`、右 `2i+2`
- 堆序不变量：每个结点都不大于它的孩子 ⇒ 堆顶 `h[0]` 就是全局最小
- 建堆正确性：从最后一个非叶结点 `n/2-1` 递减到 `0`，每个位置下沉后其子树已是堆，归纳可得整棵树是堆
- 代价：自底向上建堆的总下沉步数 ≤ Σ层高 ≈ 2n，即 O(n)；单次插入/弹堆 O(log n)

### 实操（仓颉）

- `Array<Int64>(cap, repeat: 0)` + 一个 `size` 变量当唯一真相；容量直接取 `n + m` 上界，插入时不扩容
- 下沉先挑孩子再比：`if (l + 1 < size && h[l + 1] < h[l]) { c = l + 1 }`，孩子相等取左，堆形才唯一
- 弹堆三步：存下 `h[0]` → 把 `h[size-1]` 搬到堆顶 → `size -= 1` → 只要 `size > 0` 就对新堆顶下沉
- "挖坑"写法更省：待落位元素先放局部变量，每层只把孩子往上搬，比三次交换少一半数组读写（实测 13 万次 push+pop 从 0.69 s 降到 0.45 s）
- 实测：D13-A 的 05（n = m = 2×10⁵）在 judge 里约 800 ms

### 建议（做完 D13-A 之后看）

- 别用"数组长度"推堆大小：弹出后长度不变，`size` 才是真相。自检：连做 5 次 `2` 操作，输出末尾必须是 `... 0` 和 `empty`
- 堆当优先队列时键会变（Dijkstra 的松弛就是）：不要试图"修改堆内元素"，改成 **push 新条目 + 弹出时比 `d > dist[v]` 跳过过期项**，这就是懒删除；代价是堆里最多 2m 条，换来一次更新只花 O(log n)
- 只在"要反复取极值"时用堆；只取一次极值直接线性扫更快

## 13.2 堆排序（D13-B）

### 学术

- 大顶堆 + 重复 n-1 次「堆顶与堆尾交换 → 堆大小减一 → 堆顶下沉」⇒ 尾部依次落定最大值，整体升序
- 循环不变量：`[0, size)` 内是堆，`[size, n)` 已排好且每个元素都不小于堆内元素
- 建堆结果唯一：从 `n/2-1` 往前 + 孩子相等取左 + 严格大于才交换，三个约定一起钉死堆形，所以"建堆后的数组"可以判题
- 代价：建堆 O(n) + n-1 次 O(log n) 下沉 = O(n log n)，原地排序只用 Θ(1) 额外空间

### 实操（仓颉）

- 原地排序会把数组改掉，所以**先把建堆后的数组写进输出**，再进入排序阶段
- 交换用临时变量三行；`a[size-1]` 就是当前堆尾；`while (i >= 0)` 的下标用 `Int64`，n = 1 时 `n/2-1 = -1` 才不会越界
- 实测：D13-B 的 05（n = 2×10⁵）约 820 ms，输出两行各 2×10⁵ 个数

### 建议（做完 D13-B 之后看）

- 题面只说"排序"时标准库 `sort` 更快；堆排序的价值在"原地 + 最坏也是 O(n log n) + 顺便得到堆结构"
- 自检：n = 1 与 n = 2（两个数相等）各跑一次——前者不该进任何循环，后者不该发生交换

## 13.3 Top-K 大元素（D13-C）

### 学术

- **求最大的 k 个要用小顶堆**：堆里放"已扫描元素中最大的至多 k 个"，堆顶是这 k 个里最小的，也就是当前第 k 大的阈值
- 不变量：扫完第 i 个元素后，堆内元素 = 前 i 个里最大的 `min(i, k)` 个
- 为什么对：新元素若大于当前第 k 大，它必进前 k，被挤掉的只能是堆顶；否则它不可能进前 k
- 代价：O(n log k)、空间 O(k)；全排序是 O(n log n)，k ≪ n 时堆明显更省

### 实操（仓颉）

- `size < k` 直接插入并上浮；否则只有 `v > h[0]` 才 `h[0] = v` + 下沉（写成 `>=` 会让重复值反复进出堆）
- 弹堆得到升序，倒序写出就是"从大到小"；`k == n` 退化为整排序
- 实测：D13-C 的 05（n = 2×10⁵、k = 10⁵）约 650 ms

### 建议（做完 D13-C 之后看）

- 记法：求最大 k 个用小顶堆、求最小 k 个用大顶堆——堆顶永远是"最该被淘汰的那个"（这一条是本关最容易记反的地方）
- 自检：全相同的数组、k = n/2，答案必须是 k 个同样的值；少一个就是 `>` / `>=` 写错

## 13.4 合并 K 个有序序列（D13-D）

### 学术

- 多路归并：堆里放"哪一路"，键 = `(该路当前头的值, 路编号)`
- 不变量：堆恰好包含每一路的当前头 ⇒ 堆顶就是全局的下一个输出
- 并列取编号小：把编号当第二关键字，堆序升级为全序 ⇒ 输出唯一、可判题
- 代价：O(N log k)；每步线性扫 k 个候选是 O(N·k)，k = 1000、N = 2×10⁵ 时差三个数量级

### 实操（仓颉）

- `ArrayList<ArrayList<Int64>>` 存 k 条序列，`ptr[i]` 是游标，`head[i]` 是各路当前头（键就地更新，不重建堆）
- 弹出后 `ptr[src] += 1`：未耗尽就刷新 `head[src]` 再对新堆顶下沉；耗尽则把堆尾搬到堆顶、`hs -= 1`
- 每行第一个数是长度，解析时跳过它（别把长度当元素压进堆）
- 实测：D13-D 的 05（k = 1000、N = 2×10⁵）约 770 ms

### 建议（做完 D13-D 之后看）

- N 小时"全塞进一个数组再排序"结果相同（题面允许），但 k 路的自然解法是堆；真实场景里 k 路数据往往是流式的，堆是唯一 O(N log k) 的选择
- 自检：让所有元素相同（k = 3、每行一个 5），输出必须是 `5 5 5`；若顺序依赖输入细节，说明比较器没把编号当第二关键字
