# D14 · 图的遍历

> 4 个单元，每个单元三段：**学术**（定义/不变量/为什么对）→ **实操**（仓颉写法/边界/实测）→ **建议**（做完对应题目再看）。
> 图的载体是邻接表 `ArrayList<ArrayList<Int64>>`；网格则不需要建表，靠"隐式图 + 一维化"。

## 14.1 邻接表建图 + DFS 访问序（D14-A）

### 学术

- 图 `G=(V,E)`：邻接表为每个点给出邻居集合；**无向边要在两端各记一次**
- DFS 先序 = 递归顺序：访问 v → 按既定次序取一个未访问邻居深入 → 回溯到 v 接着看下一个邻居
- 不变量：栈内自底向顶就是当前这条路径，`ptr[v]` 记录 v 已经检查到第几个邻居 ⇒ 显式栈可以**逐元素复现**递归先序
- 代价：O(n + m + Σdeg·log deg)（每张邻接表排序那一步），空间 O(n + m)

### 实操（仓颉）

- 建桶：`adj.add(ArrayList<Int64>())` 做 n 个；无向边 `adj[u].add(v); adj[v].add(u)`，下标统一减 1 或统一用 1..n
- 想要"按编号升序深入"，建完表必须 `sort(adj[i])`
- 显式栈三件套：`stack[sp]`、游标 `ptr[v]`、访问标记；栈顶没有未看邻居就 `sp -= 1`
- 一个连通块走完后，外层从最小编号的未访问点续下一块
- 实测：D14-A 的 05（n = 10⁵、m = 2×10⁵，含 10⁵ 层长链）约 670 ms

### 建议（做完 D14-A 之后看）

- 本机实测 10⁶ 层非尾递归也能正常返回，所以"爆栈"不是唯一理由；更硬的理由是**可控**：显式栈 + 游标才能保证访问序与题面约定逐字一致
- 自检：星形图（1 连 2..5）+ 两个孤立点，答案必须是 `1 2 3 4 5 6 ...`；若中间乱序，要么邻接表没排序，要么把"所有邻居一起压栈"当成了 DFS（那是 BFS 味）

## 14.2 BFS 求无权最短路（D14-B）

### 学术

- 无权图上 BFS 的层号就是最短边数：第一次访问即定型，之后不会再变短
- 不变量：队列按距离**非降序**出队，所以出队时 `dist[v]` 已是最终值
- 前驱唯一性：邻居按编号升序入队 ⇒ "第一次发现它的前驱"唯一 ⇒ 最短路本身唯一、可判题
- 代价：O(n + m)，每个点入队一次、每条边被看两次

### 实操（仓颉）

- 队列 `Array<Int64>(n+1)` + `qh`/`qt` 两个指针；`ArrayList.remove(at: 0)` 是 O(n)，10⁵ 规模会拖死
- `dist` 初值 `-1` 兼作访问标记：`if (dist[u] < 0) { dist[u] = dist[v] + 1; par[u] = v }`
- 路径回溯：从 t 顺着 `par` 走到 s，用 `ArrayList` 存下来倒着输出；`dist[t] < 0` 直接输出 `-1`
- 实测：D14-B 的 05（n = 10⁵、m = 2×10⁵）约 760 ms

### 建议（做完 D14-B 之后看）

- DFS 求最短路是错的：先到的那条未必最短；最短路必须按层扩展
- 自检：造两条等长最短路（`1-2-4-6` 与 `1-3-4-6`），答案必须是**先被发现**的那条；若你的实现会"第二次发现时覆盖前驱"，输出就跟遍历细节绑死了

## 14.3 连通块计数（D14-C）

### 学术

- 连通块是顶点集上的等价类；块数 = "需要从哪里起一次新遍历"的次数
- 外层按编号升序扫 ⇒ 每个块第一次被扫到的点就是**块内最小编号**，不必再求 min
- 孤立点自成一个块（size = 1），这是最容易漏的一类
- 代价：O(n + m)

### 实操（仓颉）

- `visited` 数组 + 显式栈（或 BFS 队列）都行，只要把整块走完
- 块内计数：每弹出一个点 `size += 1`
- 输出天然按最小编号递增，不需要额外排序
- 实测：D14-C 的 05（n = 10⁵、m = 2×10⁵）约 690 ms

### 建议（做完 D14-C 之后看）

- 并查集（D16）也能做连通块，但"一次遍历扫全图"最省事；只有在**边是动态加入**时才需要并查集
- 自检：m = 0 时应输出 n 行 `<i> 1`；块规模一个都不许错，孤立点必须出现

## 14.4 网格 BFS（D14-D）

### 学术

- 网格是**隐式图**：点 = 格子，边 = 上下左右四邻接，不需要真的建邻接表
- **一维化** `idx = x*m + y`：上下移动是 `idx ± m`，左右移动是 `idx ± 1`（必须判同行）
- 一次 BFS 得到"从 S 到每一格的最少步数"，之后每个查询 Θ(1) 查表
- 代价：O(nm + q)。如果每个查询重跑一次 BFS 就是 O(q·nm)，6.4×10⁵ 格 × 10⁵ 查询必然超时

### 实操（仓颉）

- `Array<Bool>` 存墙、`Array<Int64>` 存距离（初值 `-1` 同时表示"没访问"和"不可达"，正好是题目要的输出）
- 读网格用 `row.toRuneArray()` 再比 `r'#'` / `r'S'`：`String` 的 `[i]` 取到的是**字节**，和 `r'#'` 比永远不相等
- 左右移动先判 `cy > 0` / `cy + 1 < m`，否则会从行尾穿到下一行行首
- 实测：D14-D 的 05（800×800、22% 墙、q = 10⁵）约 450 ms

### 建议（做完 D14-D 之后看）

- 看到"静态网格 + 多组查询"先想"预处理一次、查询 O(1)"；只有起点每次不同才需要多源/多次 BFS
- 自检：查 `S` 自己必须 0、查墙必须 `-1`、查被墙围死的口袋必须 `-1`——这三个一起过，网格逻辑基本没错
