# D10 · 哈希表与集合

> 4 个单元，每个单元三段：**学术**（定义/不变量/为什么对）→ **实操**（仓颉写法/边界/实测）→ **建议**（做完对应题目再看）。
> 本关只有一个真敌人：**哈希的遍历顺序没有任何契约**。凡是"要有序输出"的题，顺序都必须由你自己给出来。

## 10.1 词频按 key 输出（D10-A）

### 学术

- 词频是"等价类计数"：映射 `值 → 出现次数`，与 key 第一次出现的位置、出现顺序都无关
- 哈希表均摊 Θ(1) 单次读写，建表 Θ(n)；但它只保证"能查到"，**不保证任何遍历顺序** —— 那不是随机，而是"无契约"
- 一旦要求确定性输出，就必须引入外部全序：取出全部 key 排序，Θ(d log d)，d 为不同 key 数
- 总代价 Θ(n + d log d)；把排序当成哈希的一部分是错的，它是独立的一步
- 正确性依据：计数与顺序正交 —— 先算完计数，再用排序决定顺序，两者互不干扰

### 实操（仓颉）

- `HashMap<String, Int64>()`；累计写 `m[k] = (m.get(k) ?? 0) + 1`，`??` 直接给缺省值，省掉一次 `contains`
- 遍历写成 `for ((k, v) in m)`；要按序输出就把 key 收进 `ArrayList<String>`，再 `sort(keys)`
- 词里只含小写字母，`sort` 的字典序与 ASCII 序一致，不用自定义比较器
- `split(" ")` 在连续空格处会产生空串，`if (p.size == 0) { continue }`
- 实测：n=10⁵（约 2×10⁴ 个不同词）的 05 用例在 judge 里约 212 ms

### 建议（做完 D10-A 之后看）

- 去重/计数一律用哈希；用 `ArrayList.contains` 线性扫词表是 O(n·d)，本题数据是 10⁹ 量级，必然超时
- 最高频错法：直接边遍历 `HashMap` 边 `print`。自检动作 —— 同一输入连跑两次，输出不一致就是没排序
- 只有"要顺序"时才排序；纯计数题（只要某个 key 的值）不需要这一步

## 10.2 集合运算（D10-B）

### 学术

- 交、并、差都是 `contains` 谓词的组合：交 = 同时在两侧，差 = 只在 A，并 = 至少在一侧
- 集合语义下 `add` 幂等：重复元素不改变 `size`，所以"去重"和"判断归属"是同一个动作
- 期望复杂度 Θ(n + m)；输出确定性同样不来自遍历，而来自排序
- 三个结果集都是"集合"，所以它们内部的元素天然互异 —— 收集时不必再去重一次
- 正确性依据：集合恒等式 A−B = A ∩ Bᶜ，两边独立算应得到相同元素集

### 实操（仓颉）

- `HashSet<Int64>`：`add(x)` / `contains(x)` / `size`，没有 `containsKey` 那套命名
- 遍历 `HashSet` 收进 `ArrayList<Int64>` 再 `sort`；空集输出 `empty`（不是空行，也不是 0）
- A−B 与并集都能在"遍历 A 一次"里分出：在 B 里算交，不在 B 里算差，同时都进并集；再从 B 补一次 `!setA.contains(x)` 即可
- 实测：n=m=10⁵、输出 1.3 MB 的 05 用例在 judge 里约 554 ms

### 建议（做完 D10-B 之后看）

- 别为交/并/差各建一个 `HashSet`：结果从已去重的 A 出发收集就够，省掉一整轮哈希插入（实测把 842 ms 压到 554 ms）
- 最高频错法：用 `ArrayList.contains` 判归属 —— n=m=10⁵ 是 10¹⁰ 次比较
- 自检动作：让 A 与 B 完全相同，第三行必须是 `empty`

## 10.3 两数之和下标（D10-C）

### 学术

- 边扫边查的不变量：处理下标 j 时，表里只有"早于 j 出现过的值 → 最早下标"，因此 `i = j` 的情况**结构上不可能发生**
- 多解口径 = (i, j) 的字典序最小；对固定 j，表给出的是最小可行 i，于是全程取 min 就能得到全局字典序最小解
- 只与历史配对，不需要回看，因此 Θ(n) 期望时间、Θ(n) 空间
- 正确性依据：最优解的 i\* 在扫描到 j\* 时，表中"该值最早下标"恰为 i\*（否则存在更小的可行 i，与 i\* 最小矛盾）

### 实操（仓颉）

- `HashMap<Int64, Int64>` 存"值 → 最早下标"，用 `0` 当"没出现过"的哨兵：`let i = firstPos.get(need) ?? 0`
- 顺序必须是**先查后插**；只在 `!contains(v)` 时插入，保证存的是最早下标
- 输出是 1 起下标，循环里用 `i+1` 一次算清楚，不要中途反复加减
- 实测：n=2×10⁵ 的 05 用例在 judge 里约 354 ms

### 建议（做完 D10-C 之后看）

- 先把整张表建好再查是错的：那样 `target = 2v` 且 v 只出现一次时会自配
- 最高频错法：撞上哪对就输出哪对。题面钉死了"i 最小、再 j 最小"，必须全程维护最优
- 自检动作：`[5, 4]` 配 `target = 8` 必须输出 `-1`；`[5, 5]` 配 `target = 10` 必须输出 `1 2`

## 10.4 分组聚合（D10-D）

### 学术

- "互为异位词"是等价关系（自反、对称、传递），所以能按等价类分组
- 键就是等价类的**规范形**（canonical form）：`a` 与 `b` 同组 ⇔ 规范形相等。字符升序重排是这里最省的一种规范形
- 输出的确定性需要两层全序：组间按键升序、组内按词升序；键本身已唯一，不会并列
- 代价：每个词 O(L log L) 造键（L ≤ 8），加 Θ(n) 建表、Θ(g log g) 排组、Θ(n log n) 排组内
- 正确性依据：规范形满足 `f(x) = f(y) ⇔ x ~ y`，分组判据因此可完全交给哈希

### 实操（仓颉）

- 造键三步：`let chars = w.toRuneArray()` → `sort(chars)` → `String(chars)`
- `HashMap<String, ArrayList<String>>`：`let bucket = groups.get(key) ?? ArrayList<String>()`，`bucket.add(w)`，再 `groups[key] = bucket` 写回
- 组内排序用 `sort(bucket)`（字典序升序），不要顺手去重
- 输出 `键 计数 词…`，第一个词前只加一个空格
- 实测：n=10⁵、约 2×10⁴ 个键的 05 用例在 judge 里约 450 ms

### 建议（做完 D10-D 之后看）

- 最高频错法：拿单词本身当键 —— 那样每个异位词各自成组，样例会直接暴露（组数变成 5 而不是 2）
- 别在组内去重：题面要求重复出现的单词重复列出
- 自检动作：`eat`、`tea`、`ate` 必须落在同一行，且组内顺序是 `ate eat tea`
